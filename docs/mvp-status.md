## 1. 結論

**PC→iPhone→PC→iPhone→PC と行き来して、最初から最後まで遊べます。**
今回、音とエフェクトの優先1と、iPhoneのタップ送りを作りました（3節）。

- 音は Web Audio API の合成音です。音声ファイルは使っていません（`sound.js`）。
  PCで `index.html` を直接開いても、音が出ることを確かめました（自動操作のブラウザ）。
- どの場面で何を鳴らすかは、`data.js` の場面に書きました。戦いの音は技に結びつけています。
- 入力欄の正解音・不正解音、1-3の戦い、2-7、最終章（4-2〜4-6）に、音とエフェクトを付けました。
- 音のON/OFFを、メニュー（≡）とタイトル画面に付けました。端末ごとに記録します。
- 第3部（外）では鳴らしません。iPhoneの家の中の場面は、短い通知音だけです。
- iPhoneのSafariでは、最初のタップまで鳴りません。鳴らせない音は捨てて進むので、止まりません。
- iPhone（メッセージ画面）の文を、自動送りからタップ送りにしました。PCは変えていません。
- セリフの文言は変えていません（13行に音の名前を足しただけ）。
- 優先2（第1部のBGM、氷の床の音など）は、まだ作っていません。
- 実物のPCのスピーカーとiPhoneでは、まだ聞いていません。音色と音量は、聞いて直す必要があります。

前回までの内容（挑戦の床、第2部の変更、ニンフィアの見直し、地図が広がる演出など）は、4節以降にあります。

### 3.2 音のON/OFFと、iPhoneの最初のタップ

- メニュー（≡）とタイトル画面に、「🔊 音：ON」「🔇 音：OFF」のボタンを付けました。
  押すたびに切りかわり、端末ごとに記録します。「記録（セーブ）を消す」では消えません。
- ON にしたときは、確かめの短い音を1回鳴らします（第3部の場面では鳴らしません）。
- はじめの設定は、`data.js` の `SETTINGS.sound`（今は `true`）です。
- 音の準備は、最初に画面をさわったときにします（iPhoneのSafariは、さわるまで鳴らないため）。
- 準備ができる前の音は、ためずに捨てます。あとでまとめて鳴ったり、ゲームが止まったりしません。
- ほかのアプリやタブに切りかえると音を止め、もどると続けます。
- マナーモードでは鳴らないことがあります（iPhoneの決まりどおり。無理に鳴らしていません）。

### 3.3 iPhoneの文の送り方（タップ送り）

| 場面 | 今回の動き |
|---|---|
| メッセージ画面（iPhone） | 次の文へ自動で進めない。画面をタップすると、次の文を出す |
| 「入力中…」が出ている途中 | タップすると、すぐに文を出す。もう一度タップすると次の文へ |
| タップを待っている間 | 最後の文の終わりに、小さな ▼ を出す |
| 選択肢・入力欄・「つづける ▶」 | 最後の文のあと、すぐに出る（今どおり、そこで止まる） |
| 言葉のカード | 前の文のあと、タップしてから出る |
| PC（物語画面） | 変えていない（戦いの地の文の自動送りも、今までどおり） |

- メッセージ画面の文は、1字ずつではなく「入力中…」の印のあとに出る形です。
  そのため、設計書の「1字ずつ出ている途中でタップ」は、「入力中…」の途中でタップ、としました。
- 「入力中…」の時間を短くしました（いちばん長くて1.7秒から0.9秒へ）。読む時間はタップで決まるためです。
- すばやくタップしても、画面が拡大されたり、文字が選ばれたりしないようにしました。
- PCでメッセージ画面を開いたとき（テスト）も、クリックで進みます。

机を一度押したあとも、机が上に重なったままでした。

- 2-2の「？？？」と、メニューの「夢の部屋の地図」でも同じことが起きていました。どちらも直りました。
- 前回の確認では、マウスを○の真上へ直接動かしていたため、見落としたと考えています。
