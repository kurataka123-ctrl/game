# 試作報告：イーブイと8つの夢の冒険（実現可能性確認版）

作成：2026年10月21日　対象：企画書「11. 今回、ゲーム作成AIに依頼すること」A〜D

---

## 1. 結論（実現可能性の評価）

**企画の大枠は、HTML・CSS・JavaScriptだけで実現できます。**
試作で、第1部（PC）から第2部（iPhone）への流れを実際に動かしました。

| 部分 | 評価 | 根拠 |
|---|---|---|
| 第1部：PCの冒険 | ◎ 実装済み | 会話・選択肢・なぞなぞ・夢の部屋の地図が動作 |
| 第2部：自宅とiPhone | ◎ 実装済み | カードの合言葉・QRコードでiPhone側の章が始まる |
| 第3部：駅・公園 | ○ 実装できる | 第2部と同じ仕組み（合言葉）で作れる。GPSは不要 |
| 第4部：TRUE END | ○ 実装できる | 最後の合言葉の入力で解放する形にできる |

ただし、条件が1つあります。
**iPhoneで遊ぶには、ゲームをインターネット上に公開する必要があります。**
駅や公園では、自宅のWi-Fiが届かないためです（→ 5章・6章）。

## 2. 推奨する技術構成とその理由

| 項目 | 推奨 | 理由 |
|---|---|---|
| 作り方 | HTML・CSS・JavaScript（追加ツールなし） | インストール不要。PCではファイルをダブルクリックで動く |
| PCとiPhone | 同じページを両方で使う | 作るものが1つで済む。修正も1か所 |
| 画面の形式 | PC＝会話枠の形式、iPhone＝メッセージ形式 | 端末が変わったこと自体を体験にできる |
| 進行の共有 | 端末ごとの自動保存＋合言葉・QRコード | サーバー不要で確実。記録が消えても再開できる |
| 内容の編集 | 文章は `story.js`、地図は `room.js` だけ | 仕組みと内容を分け、初心者が触る範囲を限定 |
| 公開 | 静的サイトの公開サービス | 無料〜低額。編集の反映が簡単 |

### 2.1 PCとiPhoneで進行状態を共有する方法の比較（企画書 A-3）

| 方法 | 難易度 | 利点 | 欠点 |
|---|---|---|---|
| ① 合言葉を入力 | 低 | サーバー不要。記録が消えても、合言葉で再開できる | 入力の手間（ただし謎解きの一部にもなる） |
| ② QRコード（URLに合言葉を含める） | 低 | カメラで読むだけ | 印刷が必要。公開URLが必要 |
| ③ 端末ごとの自動保存 | 低 | 何もしなくても続きから遊べる | 端末をまたいでは共有されない |
| ④ 復活の呪文（進行全体を文字列にする） | 中 | 細かい状態まで移せる | 入力が長い。この企画には不要 |
| ⑤ クラウド同期（Firebase等） | 高 | 自動で同期できる | アカウント・設定・管理が必要。障害で止まるおそれ |

**推奨：①＋②＋③の組み合わせ（試作で実装済み）。**
この企画は一本道なので、章の入口を合言葉で開ければ十分です。

### 2.2 現実世界との連動方法（企画書 A-4）

| 場所 | 方法 | 注意点 |
|---|---|---|
| 自宅 | カード（文章＋合言葉、必要ならQRコード） | `cards.html` で印刷できる |
| 駅・公園 | 現地でしか分からない答えを合言葉にする | 物を置かない。事前の現地確認が必要 |
| TRUE END | プレゼントの中に最後の合言葉カードを入れる | プレゼントを見つけてからゲームに戻る流れ |

駅・公園の答えの例（推測を含む案）：駅名標に書かれた隣の駅名、公園の看板の言葉。
掲示物は変わることがあるため、本番直前の確認と、予備の合言葉が必要です。

## 3. 試作した機能（企画書 B）

| 依頼内容 | 試作の状態 |
|---|---|
| タイトル画面から開始 | 「はじめから」「つづきから」「あいことばを入れる」 |
| イーブイとエーフィの会話 | 企画書6.1の会話をそのまま使用 |
| 夢の部屋の地図 | 俯瞰型の2D地図。家具を調べられる。光る場所を調べると先へ進む |
| 選択肢やボタンで進行 | 選択肢、選び直し、なぞなぞ（グレイシアの仮イベント） |
| カード発見後にiPhoneで再開 | 合言葉入力、またはQRコードで第2部（メッセージ形式）が始まる |
| ブースター・シャワーズへの仮イベント | 場所当て → カードの合言葉 → 仲間になる |
| PC・iPhoneでの表示確認 | PCは中央に枠、iPhoneは全画面。ノッチ・ホームバーに対応 |

試作で追加したもの：

- **なかまノート**：会った仲間を8つの枠で表示（4/8、6/8…）
- **印刷用カード**（`cards.html`）：文章・合言葉・QRコードをA4に4枚
- **テスト用メニュー**（`?debug`）：場面へのジャンプ、記録の消去、QR表示
- **書きまちがいの点検**：story.js の誤りを画面で知らせる
- **仮の内容の目印**：未確定のイベントに「仮の内容」と表示

### 3.1 こちらで行った動作確認

自動操作のブラウザ（Chromium）で、第1部から第2部の最後まで通しで操作しました。
確認した主な点は次のとおりです。コンソールのエラーはありませんでした。

- PC（画面幅1280px）とiPhone相当の画面（iPhone 13・iPhone SEの大きさ）で表示
- 合言葉はカタカナで入力しても正解になる
- QRコードを読むと第2部から始まる。記録があるときは「つづきから」も選べる
- 公開URLを設定したカードのQRコードを、画像から読み取って正しいURLを確認
- story.js にカンマ忘れや場面名の誤りがあると、画面に説明が出る

**未確認の点**：実物のiPhoneのSafariと、印刷したQRコードの読み取りは、
こちらの環境では確認できていません（→ 4章）。

## 5. 現時点での技術的な課題

| 課題 | 内容 | 対応案 |
|---|---|---|
| 公開範囲 | 公開URLは、知っている人なら誰でも開ける | 個人情報を載せない（下記）。検索エンジンには載らない設定済み |
| 個人情報 | 部屋の間取り・最寄り駅・公園が分かると、住所の推測につながる | 駅名・公園名・本名・住所はゲームに書かず、カードに書く |
| 実機未確認 | iPhoneのSafariで細かな表示差が出る可能性 | 4章の項目を実機で確認 |
| 記録は端末ごと | PCとiPhoneの記録は自動では共有されない | 合言葉で章を開く設計にしたため、進行に支障はない |
| ネタバレ | ページの中身を見れば、合言葉が分かる | 必要なら、合言葉を読みにくくする処理を追加できる |
| 電波 | 電波のない場所で再読み込みすると開けない | 必要なら、オフラインでも開ける仕組みを追加できる |
| 素材 | 公式の画像・音楽を公開ページに載せるのは避けたい | 絵文字のまま、または手描き・オリジナルの絵を使う |

※ 素材の権利について、私は法律の専門家ではありません。
私的に楽しむ範囲でも、公開ページに公式画像を置くことは避けるのが無難です。

## 7. 初心者が今後ゲームの内容を変更する方法

| 変えたいもの | 編集するファイル | 方法 |
|---|---|---|
| 会話・選択肢 | `story.js` | `"名前：セリフ"` の形で書く |
| 場面の追加 | `story.js` | 既存の場面をコピーして、名前と中身を変える |
| 部屋の地図 | `room.js` | 方眼紙のマス目で、家具の位置と大きさを数える |
| カードの文章 | `story.js` の `CARDS` | 変更後に `cards.html` を開いて印刷 |
| 合言葉 | `story.js` の `KEYWORDS` | 「合言葉 → 始まる場面」を書く |

確認のしかた：

1. ファイルを保存し、`index.html` を開き直す。
2. URLの最後に `?debug` を付けると、編集した場面へすぐジャンプできる。
3. 書きまちがいがあれば、画面に説明が出る。

くわしい書き方は [README.md](../README.md) にまとめました。
Claude に頼む場合は、「story.js の〇〇の場面に、△△という選択肢を追加して」
のように、場面の名前と変えたい内容を伝えると確実です。
