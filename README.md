# イーブイと8つの夢（最小構成版）

13歳の息子さんへのクリスマスプレゼントと連動した、手作りゲームです。
PCで始まり、ブラッキーのぬいぐるみのQRコードからiPhoneへ移ります。
そのあと、家の中・駅・公園へと冒険が広がり、最後はPCへ帰ってきます。

- 実装の状況・仮置きの一覧・本番までの準備 → [docs/mvp-status.md](docs/mvp-status.md)
- 以前の試作報告（2026年10月21日） → [docs/prototype-report.md](docs/prototype-report.md)

> **設計書と間取り図は、このリポジトリに入れないでください。**
> 公開ページから、答えや駅名、家の間取りが見えてしまいます。

## 1. まず遊んでみる

| 遊ぶ場所 | 開き方 |
|---|---|
| PC | `index.html` をダブルクリック（Chrome・Edge・Safari） |
| iPhone | インターネットに公開したURLを開く（→「8. iPhoneで遊ぶには」） |

PCで直接開いたときだけ、PCに保存した公式のイラストを使えます（→「7. PCで公式のイラストを使う」）。

- 記録は端末ごとに自動で保存されます。次回は「つづきから」で再開できます。
- iPhone（メッセージ画面）の文は、画面をタップすると1つずつ進みます。
  文の終わりの ▼ が、タップを待っている印です。PCの会話の送り方は、今までどおりです。
- PCでは、Enter（またはスペース）でも文が進みます。
  メニュー（≡）やなかまノートを Esc で閉じたあとも、Enter は文を進めます（メニューはまた開きません）。
  メッセージ画面の「つづける ▶」も、PCでは Enter（またはスペース）で押せます（押しっぱなしでは押しません）。
- PCでは、会話の枠の左下の「ログ」か ↑キーで、今の場面で出た文を読みかえせます（→「バックログ（PC）」）。
  iPhone（メッセージ画面）は、画面を指で下へなぞると、前の文へさかのぼれます。
- 音が鳴ります（PCは全部、iPhoneは短い音だけ、第3部の外では鳴らない）。
  PCの場面では、曲（BGM）も流れます（第1部・1-3の戦い・最終章）。
  メニュー（≡）とタイトル画面の「🔊 音：ON」で、音と曲をまとめて切れます（→「音とエフェクト」）。
- PCとiPhoneの記録は別々です。端末を移るたびに合言葉でつなぎます。
  合言葉の場面で、それまでに会った仲間と言葉を引きつぎます。
- 「あいことばを入れる」から、合言葉で途中の章を始められます。
- タイトル画面とメニュー（≡）の「なかまの場面へ」から、クリアした仲間の場面を最初から遊べます。
  遊び直しても、いちばん先まで進んだ所は減りません。「つづきから」で、その所から再開します。
  最終章を終えたあとは、PCの3匹は、終えたら「なかまの場面へ」のメニューへ戻ります
  （→「クリアしたなかまへ戻る（REPLAY）」）。
- 最終章を終えると（4-6の終わりの画面のあと）、PCのタイトル画面に「🎁 おたのしみ」が出ます
  （→「クリア後のおたのしみ（BONUS）」）。タイトル画面の「なかまの場面へ」は、その中に入ります。

| 順 | 合言葉 | 入れる端末 | 始まる場面 |
|---|---|---|---|
| 1 | `ゆめのへや`（ブラッキーのQRコードと同じ） | iPhone | 2-4 ブラッキーとの通信 |
| 2 | 鏡に浮かんだ駅名（暗号で比べる） | PC | 2-7 エーフィの地図 |
| 3 | `まどのそと`（PCの画面に出る） | iPhone | 3-0 出発 |
| 4 | `ただいま`（iPhoneの最後に出る） | PC | 最終章 |

### テスト用メニュー

URLの最後に `?debug` を付けて開くと、右下に 🛠 ボタンが出ます。

- 好きな場面へジャンプ
- なかまと言葉を全部そろえる／記録（セーブ）を消す／最終章を終えた記録をつける（「おたのしみ」を試す）／気配の記録を消す（公園で見つけた記録だけ）
- 遊ぶ前の準備：友達の呼び名を変える・プレゼントの場所を決める（→「6. 合言葉・カード・当日の設定」）
- 答えを暗号にする／表示用に隠す（→「4. 答えを暗号にする」）
- 合言葉のQRコードを表示（公開したページで開いたときだけ）
- 氷の床の最短回数（自動で数えた結果）と、data.js の点検結果を表示
- 戦いの点検：戦いごとに、何ターンで勝てるか・攻撃だけだとどうなるか・大技の予告のときだけ防ぐとどうなるか・でたらめに選ぶと何%勝てるか
- 音の試聴：音を1つずつ鳴らす（音が OFF でも鳴る。iPhone はマナーモードを切ってから）

例：`index.html?debug`（PCでは、アドレス欄の最後に `?debug` を書き足す）

## 2. ファイルの役割

| ファイル | 中身 | 編集する？ |
|---|---|---|
| `data.js` | 会話・選択肢・言葉・合言葉・カード・画面の文字（ボタンなど） | **よく編集する** |
| `room.js` | 夢の部屋の地図（家具の位置と、調べたときの文章） | 実際の部屋に合わせて編集 |
| `house.js` | 第1部で歩く地図と、2-7の家全体の地図（部屋の形・家具・会った仲間の印の場所） | 実際の家に合わせて編集 |
| `cards.html` | 印刷用カードのページ | ふつうは不要 |
| `index.html` | ゲームの入口 | ふつうは不要 |
| `engine.js` | ゲームを動かす仕組み（文章は書かない） | 不要 |
| `geo.js` | 公園で気配を探す仕組み（GPSヒント機能）の判定の計算（文章・設定値・座標は書かない） | 不要（設定値と文は `data.js`） |
| `gps-test.html` | GPSヒント機能のテストページ（`data.js` と `geo.js` を読む。本編の記録には触れない） | 不要 |
| `sound.js` | 音を鳴らす仕組み（効果音は Web Audio の合成音。曲は `bgm` フォルダの mp3） | 不要（どの場面で何を鳴らすかは `data.js`） |
| `bgm/` | 曲（BGM）の音声ファイル3つ（BGMer のフリー素材。→「音とエフェクト」） | 不要（曲を差しかえるときだけ） |
| `style.css` | 色や大きさ | 色を変えたいときだけ |
| `icon.png` | iPhoneのホーム画面用アイコン | 差しかえ可 |
| `lib/qrcode.js` | QRコードを作る部品（外部・MITライセンス） | 不要 |
| `pc-images/` | PCだけで使うイラストと名前の一覧（自分で作るフォルダ。GitHub に入れない） | 使うときだけ（→ 7章） |
| `name.sample.js` | 名前の一覧（`pc-images/name.js`）の見本。架空の名前が入っている（ゲームは読みこまない） | コピーして使う（→ 7章） |
| `.gitignore` | `pc-images/` と `name.js` を GitHub に入れないための設定 | 不要 |

**文章は `data.js` にあります。**
セリフやボタンの文字を直すときは、`data.js` だけを編集します。
家具を調べたときの短い文章だけは、地図のファイル（`room.js`・`house.js`）の家具の行にあります。
選択肢を足す・場面の順番を変えるといった変更も `data.js` で行えますが、
流れが変わるので、`?debug` の点検で問題が出ないか確かめてください。

**編集するときの注意**

- 保存するときの文字コードは **UTF-8** にしてください（文字化け防止）。
- メモ帳でも編集できますが、[Visual Studio Code](https://code.visualstudio.com/)
  などのエディタを使うと、書きまちがいに気づきやすくなります。
- GitHub のサイト上でも、ファイルを開いて鉛筆マークから直接編集できます。

## 3. 文章を変える（data.js）

会話は `"名前：セリフ"` の形で書きます。名前がない行は地の文になります。

```js
lines: [
  "……ここは、どこだろう。",                 // 地の文
  "イーブイ：あれ？　見かけない顔だね。",     // イーブイのセリフ
],
```

- 行の最後のカンマ `,` を忘れないでください。
- 文章の中で改行したいときは `\n` と書きます。
- `{ }` で囲んだ言葉は、ゲームが置きかえます。

| 書き方 | 置きかわるもの |
|---|---|
| `{name}` | 主人公の名前（1-1でPCに、2-4でiPhoneに入力したもの） |
| `{friend1}`〜`{friend3}` | 友達の呼び名（`SETTINGS` の `local`。「表示用に隠す」形で書いてある） |
| `{station}` | 鏡に書く駅名（`SETTINGS` の `hidden` から） |

名前は遊ぶ人が入力します。公開ページに名前を書かないためです。

### 条件つきの行（if・unless）

選んだ道や設定によって、出す行を変えられます。

```js
lines: [
  { unless: "indoor", text: "サンダース：おっそーい！　待ってるあいだに、駅を3周しちゃったよ！" },
  { if: "indoor", text: "サンダース：おっそーい！　待ちきれなくて、窓の外まで走ってきちゃったよ！" },
],
```

- `if` はその条件のときだけ、`unless` はその条件ではないときだけ出します。
- 条件の名前は、選択肢の `set` で記録したものか、`SETTINGS` の設定です。
- 選択肢（`choices`）にも、同じように `if`・`unless` を書けます。

| 条件の名前 | 意味 | 決まり方 |
|---|---|---|
| `indoor` | 外へ出られない日（家の中で進める） | 3-0の選択肢で記録 |
| `useMirror` | 浴室の鏡に駅名を書く日 | `SETTINGS` で切りかえ |
| `presentOnMap` | プレゼントを地図で光らせる | `SETTINGS` で切りかえ |
| `roomMap` | メニューに夢の部屋の地図を出す | 2-2の場面で記録 |
| `houseMap` | メニューの地図を、家全体の地図にする | 2-7・4-1の場面で記録 |
| `presentShown` | メニューの家の地図にも、プレゼントの星を出す（`presentOnMap` のとき） | 4-5の場面で記録 |
| `friend1` `friend2` `friend3` | 友達1〜3が仲間になった（ひとりずつ） | 1-3の花畑で記録 |
| `humans` | 友達に一度でも話しかけた。2-7のセリフにも使う | 1-3の花畑で記録 |
| `pcDirect` | PCで `index.html` を直接開いている（公開ページでは、いつも「ではない」） | 開き方で決まる（記録しない）。4-6の終わりの画面の「友情出演」に使う |

### 場面（シーン）を追加する

場面には、半角英数字の名前を付けます（例：`jolteon_station`）。

```js
  jolteon_station: {
    bg: "station",                 // 背景
    lines: [
      "サンダース：ビリビリッ！　来たな！",
    ],
    next: "つぎの場面の名前",       // 会話が終わったら進む場面
  },
```

| `snow` | `true` で、その場面のあいだ雪をふらせる（終わりの画面にふらせるときは、`end` に `snow: true`） | `snow: true` |
| `knock` | 暗い窓の画面（iPhone）。画面は暗い窓とこの文だけになり、タップすると `next` へ | 2-7の `phone_window` を参照 |
| `resume` | 「つづきから」で再開するときに、代わりに始める場面 | `resume: "phone_window"` |
| `search` | 公園で気配を探す（iPhone。GPSヒント機能）。必要な数の公園で見つけたら `next` へ | 下の「公園で気配を探す」を参照 |
| `parkReset` | `true` で、その場面に入ったときに、公園で見つけた記録を空にする | 3-0の `out_start` |

- `meet` と `give` に `[ ]` で何匹も書くと、お知らせなしで、まとめて記録します。
  合言葉で始まる場面で、それまでの仲間と言葉をそろえるために使います。
- `end` に `next` を書くと、終わりの画面にボタンが出ます。
  開き直して「つづきから」を押すと、終わりの画面から再開します。
- `lines: []` と `end` だけの場面にすると、会話をくり返さずに、終わりの画面へもどれます。
  2-2の終わりの画面（`light_room_end`）がこの形です。2-7で「まだ」を選ぶと、ここへもどります。
- `afterWord` は、言葉のお知らせのあとに出ます（2-4のイーブイ、2-6のブースター）。
  `give` に1匹の名前を書いた場面で使います。
- `glow` は、4-3のイーブイの答え（`final_answer`）で使っています（10/30）。
  行に `glow: ["eevee", "glaceon"]` と書くと、その行はその仲間だけを光らせます。`glow: []` で、だれも光らせません。
  行に `glow` がなければ、話す1匹だけを光らせます。光り方は控えめです（`style.css` の `.char.glow`）。
  行に `dim: true` と書くと、その行は光らない仲間を暗くします（10/31）。
  暗さは、`glow` のない場面で話し手のほかを暗くするのと同じです（`style.css` の `.char.dim`）。
  4-3では、イーブイの1〜8行目と、8匹の返事の行に書いています。
  `show` で並べた仲間に使います。メッセージ形式（iPhone）や、地図・戦いの場面では光りません。
- 行に `image: "kaisou/グレイシア.png"` と書くと、PCで `index.html` を直接開いたときだけ、
  その行のあいだは、ゲーム画面の部分（会話の枠より上）にその絵を出します（11/2。4-3の回想のイラスト）。
  場所は `pc-images` フォルダの中で書きます。絵は切り取らずに全体を収め、余白は黒です。
  絵が変わる行（出す・別の絵にする・消す）では、暗転（場面の `imageFade`）をはさんでから文を出します。
  画像が見つからない行は、絵を出さずに `glow` の形で進みます。公開ページ（iPhone）では、画像を読みにいきません。

  ```js
  final_answer: {
    show: ["eevee", "glaceon", /* … 9匹 */],
    glow: true,
    lines: [
      { wait: AFTERGLOW },   // 約8秒の余韻（data.js の AFTERGLOW。文を出さない。Enter やタップでも進まない）
      { text: "イーブイ：グレイシアに教わったのは、…", glow: ["eevee", "glaceon"], dim: true,
        image: "kaisou/グレイシア.png" },   // PCで絵があれば絵を出す。なければ、イーブイとグレイシアが光り、ほかは暗く
      { text: "イーブイ：どれもすてきで、…", glow: [] },                                // だれも光らせない
      { text: "グレイシア：……答えを急がなくていいわ。…", dim: true },                    // 話すグレイシアだけ光り、ほかは暗く
    ],
  },
  ```
- `knock` と `resume` は、2-7のiPhone側で使っています（10/30）。
  ブラッキーが「窓を閉じて、ここで待っている」と言ったあと、画面は暗い窓だけになります（`phone_window`）。
  画面をタップすると、ブラッキーが「おかえり」と話しかけ、合言葉の入力欄が出ます（`phone_back`）。
  入力欄の「◀ まだ」で暗い窓へもどります。`phone_back` で開き直しても、「つづきから」は暗い窓から始まります。

### 声だけの人物（voice）

`CHARACTERS` で `voice: true` にした人物は、姿を出さずに名前の札だけ出します。
今は「ブラッキーの声」「エーフィの声」「ニンフィアの声」（1-3の弟戦）で使っています。

### 氷の床のパズル（ice）

すべり出すと、岩・かべ・ゴールにぶつかるまで止まれないパズルです。
矢印キー（W A S D でも可）、画面のボタン、スマホのスワイプで動かします。

```js
  glaceon_ice2: {
    walk: "washitsu",                        // 和室の形（house.js）の氷の床にする
    lines: ["氷の床に、新しい岩がいくつも現れている。"],
    ice: {
      help: "岩で止まって、向きを変えよう。",   // 遊んでいる間に出す説明
      best: 5,                                // 最短の回数（点検で確かめる）
      map: [                                  // . 氷 / # 岩 / S スタート / G ゴール
        "..G.#....",
        ".#.......",
        "...#.#..S",
        ".#.......",
        "#........",
        "..#.....#",
      ],
      clear: "グレイシア：よく来たわね。",      // クリアしたあとのセリフ
      skip: { after: 3, text: "むずかしい……", reply: "グレイシア：迎えに行くわ。", next: "glaceon_2" },
    },
    next: "glaceon_2",                       // クリアしたあとに進む場面
  },
```

- `S`（イーブイ）と `G`（グレイシア）は、1つずつ書きます。
- `G` にぶつかるとクリアです。クリアすると、最短の回数と比べて表示します。
- `skip` を書くと、「やりなおす」を `after` 回押したあとに、あきらめるボタンが出ます。
  `after: 0` なら、はじめから出ます（任意の挑戦の床）。
- `walk` を書くと、`house.js` のその部屋の形（かべ・出入口）で表示します。
  `map` の大きさ（横と縦のマス数）を、`house.js` の部屋の `w`・`h` に合わせてください。
- 盤面を変えたら、`?debug` の点検を見てください。
  🛠 の「氷の床の最短回数」に、自動で数えた最短の回数が出ます。
  `best` とちがうときや、たどりつけないときは、点検結果にも出ます。
- 今の盤面：練習（`glaceon`）は最短2回、本番（`glaceon_ice2`）は最短5回、
  挑戦の床（`glaceon_ice3`）は最短8回。
  どれも解き方は1通りで、行き止まりになる場所はありません。
- 挑戦の床は任意です。言葉をもらったあと、グレイシアに誘われて選びます（`glaceon_more`）。
  「先へ進む」を選んでも、途中で「やめて先へ進む」を押しても、1-3へ進みます。

### 歩けるマップ（walk・events）

第1部の森・花畑・小道・光の広場は、升目の地図を1マスずつ歩きます。
地図の形と家具は `house.js`、人物と出来事は `data.js` の場面の `events` に書きます。

| 操作 | PC | ボタン |
|---|---|---|
| 歩く | 矢印キー（W A S D でも可） | 右の矢印ボタン |
| 目の前を調べる・話しかける | Enter かスペース | 真ん中の「しらべる」 |

- 人物に向かって歩いても、話しかけられます。
- 目の前に調べられるものがあると、オレンジの点線の印が出ます。
- 出入口（門や扉）は、通りぬけようとすると、その出来事が起きます。

```js
  sylveon: {
    walk: "living",                     // house.js の地図の名前
    start: [7, 6, "up"],                // 歩き始める場所 [x, y, 向き]
    lines: ["ニンフィア：一緒に探して！"],  // 歩き始める前の会話
    goal: "花畑で、仲間を探そう。",       // 歩いている間に出す目的
    events: [
      // 人物：npc（キャラクター）と at（場所）。話しかけると say を出す
      { npc: "bee", at: [7, 4], say: ["ミツバチ：あの雪だるま、兄弟なんだって。"] },
      // 同じ人物を何個も書いたときは、条件に合う最初のものが使われる
      { npc: "sylveon", at: [6, 5], need: 3,
        say: ["ニンフィア：そろったね！"], next: "sylveon_snow" },
      { npc: "sylveon", at: [6, 5], say: ["ニンフィア：まだ足りないみたい。"] },
      // 出入口：door に house.js の出入口の名前。next で次の場面へ
      { door: "path", next: "path_go" },
    ],
  },
```

| events の項目 | 意味 |
|---|---|
| `npc` / `at` | 人物と場所。何人も並べるときは `npc: ["a", "b"], at: [[1, 2], [3, 4]]` |
| `door` | `house.js` の出入口の名前（`edges` の `id`） |
| `say` | セリフ（`lines` と同じ書き方） |
| `set` / `unset` | セリフのあとに、条件の名前を記録する／消す |
| `choices` | セリフのあとの選択肢。`next` がない選択肢は、返事のあと歩くのにもどる |
| `next` | セリフのあとに進む場面 |
| `if` / `unless` | 条件に合うときだけ、その人物・出来事を出す |
| `need` | 集まった仲間（場面の `team`）が、その人数以上のときだけ出す |
| `hidden: true` | 人物の姿を地図に出さない（ぶつかる・調べると話しかけたことになる）。家具のマスにも置ける（強いモードのパパ） |

友達を仲間に誘う場面は、選択肢で書いています（1-3の `sylveon`）。

```js
{ npc: "friend3", at: [13, 1], unless: "friend3",
  say: ["{friend3}：野宿する？"],
  choices: [
    { text: "はい", reply: ["{friend3}：野宿確定", "{friend3}が仲間になった！"], set: "friend3" },
    { text: "いいえ", reply: "{friend3}：そっかー。" },   // 仲間にならない。また話しかけられる
  ] },
// 3人そろったら、ニンフィアが戦いに行くか聞く
{ npc: "sylveon", at: [6, 5], need: 3, say: ["ニンフィア：雪だるまを、追い返しに行く？"],
  choices: [{ text: "行く", next: "sylveon_snow" }, { text: "もう少し花畑を見てまわる", reply: "…" }] },
```

- 場所は、地図の左上を `[0, 0]` として、右へ x、下へ y と数えます（`house.js` と同じ）。
- 歩いている途中の場所は記録されます。会話から戻ったときや、「つづきから」で、
  その場所から再開します（はじめの会話はくり返しません）。
- 人物を動かしたら、`?debug` の点検で「たどりつけないかもしれません」と出ないか確かめます。
- 歩けるマップの場面には、`next`・`choices`・`input`・`end` を書きません。
  次の場面へは、`events` の `next` で進みます。

#### 1-1の森（自分のコマ・ついてくる仲間）

1-1の森（`forest`・`forest_go`）だけは、自分のコマが主人公です。
茂みを調べてイーブイに会うと、そのあとはイーブイがうしろをついてきます。

```js
  forest: {
    walk: "forest",
    player: "hero",                 // 自分のコマ（書かなければイーブイ）
    start: [1, 0, "down"],
    intro: { dark: 2000, appear: 2000 },   // はじめの演出（下の注）
    lines: ["気がつくと、見知らぬ森の中に立っていた。", "（……ここ、どこだろう？）", "少し先の茂みで、何かがくしゃみをした。"],
    goal: "くしゃみが聞こえた茂みを、調べてみよう。",
    events: [
      { npc: "bush", at: [1, 6], next: "forest_meet" },   // 茂み（CHARACTERS の bush）を調べると、会話の場面へ
    ],
  },
  forest_go: {
    walk: "forest",
    player: "hero",
    follow: { who: "eevee", at: [1, 6] },   // ついてくる仲間と、はじめにいる場所
    goal: "洞窟の入口から、氷の洞窟へ行こう。",
    events: [{ door: "washitsu", next: "glaceon" }],   // 和室の窓（洞窟の入口）から 1-2 へ
  },
```

- ついてくる仲間は、自分が1マス歩くと、自分がいたマスへ来ます。道はふさぎません。
- `follow` の `at` は、自分のとなりのマスにします（茂みを調べた場所のとなり）。
  となりでないときは、自分と同じマスに重なって出て、歩き出すとうしろに出てきます。
- ついてくる仲間を調べると「イーブイだ。」と出ます（UI の `walkThing`）。
- 茂みは道をふさいでいるので、イーブイに会うまで洞窟の入口へは行けません。
- 森は縦に長いので、`house.js` の `view`（一度に見せる縦のマス数）を書いています。
  自分のまわりだけを大きく見せ、歩くと地図が上下に動きます。
- `intro` は、はじめの演出です（11/2。設計書 1-1）。タイトルの「はじめから」で始めたときだけ行います。
  画面が `dark` ミリ秒（2秒）かけて暗くなり、続いて森のマップが `appear` ミリ秒（2秒）かけて現れます。
  第1部の曲も、マップが現れるのに合わせて、小さい音から始まります。そのあと `lines` の3つの文が出ます。
  演出のあいだは、Enter・スペース・クリックで飛ばせます（すぐにマップを出して、文へ進みます）。
  「つづきから」・合言葉・テスト用メニューで森から始めたときは、暗転せずに文から始まります。
  「なかまの場面へ」には1-1がないので、演出は出ません。
- 「（……ここ、どこだろう？）」は主人公の心の声です。名前の札は出しません（地の文と同じ見た目）。

### 戦い（battle・BATTLES・MOVES）

1-3の花畑の戦いは、ドラクエ風の選択式バトルです。
10/28の見直しで、雪だるま兄弟との2戦にしました（弟戦 → 合体の会話 → 合体戦）。

| 場面 | 戦い（`BATTLES` の名前） | 戦う仲間 | 相手 |
|---|---|---|---|
| `sylveon_snow` | （戦いの画面なし） | ニンフィアとイーブイが、雪だるま兄を引きつける | 雪だるま兄 |
| `sylveon_battle` | `little`（弟戦） | 主人公＋友達3人（人間組） | 雪だるま弟（ハート13） |
| `sylveon_merge` | （会話だけ） | ニンフィアとイーブイがもどってくる | ― |
| `sylveon_battle2` | `merged`（合体戦） | イーブイ＋人間組＋ニンフィア | 合体雪だるま（ハート27） |

- 毎ターン、人間組4人のコマンドを選びます（クリック、または数字のキー）。
  Backspace（または Esc）で、ひとつ前の仲間の選び直しができます。
- 合体戦のイーブイとニンフィアは、決まった動きをします（コマンドは選びません）。
  イーブイは毎ターン「てだすけ」で主人公の技を2倍にし、ニンフィアは最後にリボンで決めます。
- ハートはみんなで共通の6つです。0になると負けです。相手のハートを0にすると勝ちです。
- 数値は固定で、乱数は使いません。
- 雪だるまは、雪玉のあと大きく息をすいこみ、次のターンに ふぶきを出します。
  ふぶきは、主人公の「かまくらを作る」で防げます。画面の上にも予告が出ます。
- 弟戦では、2ターン目の始めに「ニンフィアの声」が、ふぶきの合図とかまくらを教えます。
- 合体雪だるまは、転がるたびに大きくなり、雪玉が強くなります（−2 → −3 → −6）。
  5ターン目の特大の雪玉はハートが満タンでも耐えられないので、その前に勝ちます。
- 合体雪だるまの最後の3つのハートは、ニンフィアのリボン（決め技）でしか減りません。
  ハートが3つになったターンに、ニンフィアがリボンでつかまえて決めます。
- 負けたら、ヒントを聞いて、その戦いの最初からやり直します（合体戦で負けても、弟戦にはもどりません）。
- 3回負けると、ニンフィアに手伝ってもらうボタンが出ます。

| 仲間 | コマンド1 | コマンド2 |
|---|---|---|
| 主人公 | 雪玉を投げる（1ダメージ） | かまくらを作る（そのターンのふぶきを防ぐ。雪玉は防げない） |
| 友達1 | ピンポンアタック（2回当たる） | 雪玉を投げる |
| 友達2 | ぶんぶんハローYouTube（2ターン、みんなの攻撃+1） | 雪玉を投げる |
| 友達3 | ベンチホテル（ハート+3） | 雪玉を投げる |
| イーブイ（合体戦） | てだすけ（毎ターン。主人公の技を2倍） | ― |
| ニンフィア（合体戦） | リボン（相手のハートが3以下のとき。決め技） | ― |

| 相手 | ハート | 動き（ターンごとに、上から順にくり返す） |
|---|---|---|
| 雪だるま弟 | 13 | 雪玉（−2）→ ふぶき（−6） |
| 合体雪だるま | 27 | 雪玉（−2）→ ふぶき（−8）→ 大きな雪玉（−3）→ ふぶき（−8）→ 特大の雪玉（−6） |

```js
const BATTLES = {
  merged: {
    title: "VS 合体雪だるま",   // 画面の左上に出す名前
    hearts: 6,                  // みんなのハート
    leader: "hero",             // かならず戦うキャラ
    party: [                    // 上から順に動く
      { who: "eevee", tactics: ["helpinghand"] },                 // tactics：決まった動き（さくせん）
      { who: "hero", commands: ["snowball", "kamakura"] },        // commands：毎ターン選ぶコマンド
      // …
      { who: "sylveon", tactics: [{ move: "ribbon", foe: 3 }] },  // 相手のハートが3以下のとき
    ],
    enemy: {
      who: "snowMerged", hearts: 27,
      last: 3,                                      // 最後の3つは、決め技（finish）でしか減らない
      dodge: "でも、合体雪だるまは すばやく転がって、よけた！",
      actions: [                                    // ターンごとに、上から順にくり返す
        { text: "合体雪だるまの 雪玉！", damage: 2, after: ["…大きく息をすいこんだ……！"] },
        { text: "合体雪だるまの ふぶき！", damage: 8, big: true, alert: "❄ …ふぶきが来る！" },
        // …
      ],
    },
  },
};
```

| 項目 | 意味 |
|---|---|
| `commands` | その仲間が選べるコマンド（`MOVES` の名前）。書かずに `tactics`（さくせん）を書くと、自動で動く |
| `tactics` の条件 | `hearts`（みんなのハートがその数以下）・`cheer`（力アップ中か）・`foe`（相手のハートがその数以下） |
| `enemy` の `last` / `dodge` | 最後の何個のハートは決め技でしか減らないか／そのとき、ほかの技をよけた文 |
| `actions` の `big` | 「防ぐ」技（`kind: "guard"`）で防げる大技 |
| `actions` の `alert` / `after` | その行動をするターンに、画面の上に出す予告／行動のあとの文 |
| `actions` の `heal` | 相手のハートがもどる数（今は使っていない） |
| `hints` / `lose` / `skip` | 戦っている間のヒント／負けたときのヒント／あきらめるボタン |
| `choose` | 仲間をえらんで戦うときの人数（今は使っていない） |

- 技（`MOVES`）の種類は、`attack`（攻撃）・`heal`（回復）・`cheer`（全員の力アップ）・
  `guard`（大技を防ぐ）・`charge`（次のターンの攻撃を強くする）・`help`（てだすけ）です。
- `finish: true` の攻撃は決め技です（ニンフィアのリボン）。相手の残りのハートを全部へらします。
- 防ぐ技の `miss` は、防げない攻撃が来たときの文です（「雪玉は かまくらでは防げない！」）。
- 数値や技を変えたら、`?debug` の 🛠 →「戦いの点検」を見てください。
  戦いごとに、最短で何ターンで勝てるか、攻撃だけを選ぶとどうなるか、
  大技の予告のときだけ防ぐとどうなるか、でたらめに選ぶと何%勝てるかを、自動で調べて表示します。
  どう選んでも勝てない戦いがあると、点検結果にエラーが出ます。
- 戦いの地の文は、1.1秒たつと自動で進みます（`SETTINGS` の `battleAuto`。0でクリック待ち）。
  キャラクターのセリフは、いつもクリックを待ちます。

### 家全体の地図（house・作る順番5）

2-7で、夢の部屋からリビング、家全体へと地図が広がります。
4-3（8匹が集まる）と4-5（プレゼントの星）でも、同じ地図を使います。

- 場面に `house: { … }` と書くと、はじめの地図を出します。
- `lines` の中に `{ house: { … } }` と書くと、その行で地図が変わります（文は出ません）。
- 見えていない部屋は白い霧の中です。部屋が増えると、地図が広がって見えます。

```js
  espeon_map: {
    house: { show: ["dream"] },                 // はじめは夢の部屋だけ
    lines: [
      "エーフィ：その名前……。",
      { house: { show: ["path", "living"] } },  // リビングへ広がる（まだ花畑の見た目）
      "夢の部屋の地図が、リビングへ広がっていく。",
      { house: { home: ["path", "living"] } },  // 本当の家具の見た目に変わる
      "花畑の景色が、すうっと家具の形に変わった。",
      // …
    ],
  },
```

| `house` の項目 | 意味 |
|---|---|
| `show` | 見せる部屋（`house.js` の地図の名前）。`"all"` で全部。夢の見た目で現れる |
| `home` | 本当の家具の見た目に変える部屋（`"all"` で全部） |
| `marks` | `true` で、会った仲間の印を出す（場所は `house.js` の `marks`） |
| `fog` | `true` で、家の外の霧を見せる |
| `star` | `true` で、プレゼントの星を出す（場所は「遊ぶ前の準備」で決める） |
| `light` | `true` で、夢の部屋に光が集まる（4-3） |
| `tokens` | 夢の部屋に出す仲間。場面の `house` なら、はじめからいる仲間。`lines` の中なら、その行で一度に現れる（4-3） |
| `appear` | `true` で、話した仲間が1匹ずつ増えていく。`"one"` で、話す1匹だけを出す（次の1匹が現れると、前の1匹は消える）。`tokens` で出した仲間は消えない（4-3） |

- `{ if: "presentOnMap", house: { … } }` のように、条件つきでも書けます（4-5）。
- 4-3（`final_gather`）は `appear: "one"` です。話す1匹だけが、その言葉の前に現れます。
  イーブイの「……みんな、そろった。」の前の `{ house: { tokens: [8匹] } }` で、8匹全員が一度に現れます。
  仲間が現れる場所は、はじめて現れた順に決まります（一度消えても、同じ場所にもどる）。
- 2-7のあとは、メニューと終わりの画面の地図が「家の地図」になります。
- メッセージ形式（iPhone）の場面では、地図は出ません。

### 音とエフェクト（設計書 第13節）

効果音は `sound.js` が、Web Audio API でその場で合成します。効果音の音声ファイルは使いません。
PCで `index.html` を直接開いても鳴り、GitHub に効果音の音源を置かずに済みます。
曲（BGM）だけは、`bgm` フォルダの音声ファイル（mp3）を鳴らします（下の「曲（BGM）」。10/30）。
どの場面で何を鳴らすかは、`data.js` の場面に書きます。

| 場面 | 音 | エフェクト |
|---|---|---|
| 入力欄（全体） | 正解音と、責めない軽い不正解音 | なし |
| 全体（PCの場面） | 文字送りの短い音（文字が1文字ずつ出るとき、2文字ごとに1回） | なし |
| 1-2 氷の床 | すべる音、ぶつかる音。挑戦の床で最短記録を出したときの音 | なし |
| 1-3 戦闘 | 友達3人の技の音、ふぶきの前に息を吸いこむ音、合体で転がる音 | 攻撃を受けたら画面がゆれる。決め技でリボンが全員を線でつなぐ |

**鳴らし方の決まり**

- PCの場面は、全部の音が鳴ります。
- iPhoneの場面（`mode: "chat"`）は、短い通知音（正解音・不正解音、2-4の通知音）だけ鳴ります。
  文字送りの音は、PCの場面だけです（iPhoneの場面は、文字を1文字ずつ出さないため）。
- 文字送りの音は、空白・「、」「。」「…」・かっこなどでは鳴りません。
  文の行に自分の音（`sound`）があるときは、その音が聞こえるように、文字送りの音を鳴らしません（2-1のノイズなど）。
  クリックで文を最後まで出したときも、そこで止まります。
- 第3部（外）の場面は `mute: true` で、音を鳴らしません（家の中で進める日も同じ）。
- 音のON/OFFは、メニュー（≡）とタイトル画面のボタンで切りかえます。端末ごとに記録します。
  はじめの設定は `SETTINGS.sound`（`true` で鳴らす）です。「記録を消す」では消えません。
- iPhoneのSafariでは、最初に画面をタップするまで鳴りません。
  鳴らせないときは何もせずに進むので、ゲームは止まりません。マナーモードでは鳴らないこともあります。
- 音だけを手がかりにしていません。ふぶきの合図は、今までどおり文と画面の予告でも出ます。
- 音は技と場面に結びつけています。戦いの数値を変えても、音を作り直す必要はありません。
- 画面を白く光らせる演出は使っていません。答えの列を光らせるのは、正解したあとだけです。
  イーブイの答え（4-3）で光らせるのは、話す仲間の丸のまわりだけです（点滅しない）。
- ポケモンのゲームやアニメの曲・効果音には似せていません。

**書き方**

```js
// 文の行に sound を書くと、その文を出すときに鳴らす（文はそのまま）
{ text: "グレイシア：ずいぶんにぎやかになったわね。……悪くないわ。", sound: "ice" },
// 演出の行（文は出さない）：地図を変える・音を鳴らす・くり返す音を始める・待つ

{ house: { home: ["path", "living"] }, sound: "furniture" },   // 家具に変わる瞬間に鳴らす
{ house: { fog: true }, ambient: "wind" },                     // 霧の風を、場面が終わるまでくり返す
{ wait: 3000 },                                                // 待つだけ（場面のはじめに置くと、文を出す前の余韻）
// 技の音（MOVES）。相手の行動の文にも書ける
pingpong: { name: "ピンポンアタック", /* … */ sound: "pingpong" },
```

### 選択肢（choices）

```js
choices: [
  { text: "一緒に行こう", next: "glaceon" },
  { text: "どうして頼むの？", reply: "イーブイ：……それじゃ、だめかな。" },
  { text: "今日は家の中で進める", set: "indoor", next: "jolteon_meet" },
],
```

- `next` がある選択肢 → `reply`（返事）を表示してから、その場面へ進みます。
- `next` がない選択肢 → `reply` を表示して、選び直しになります（まちがいの選択肢に便利）。
- `set` を書くと、条件の名前を記録します（`unset` で消す）。

### おまけクイズ（quiz）：3-1 サンダースの駅・電車のクイズ

会話（`lines`）のあとに、選択肢の問題を1問ずつ出します。
正解しなくても進みます。ヒントも答え直しもありません。
正解でも不正解でも解説を出し、最後に正解数のセリフを出して、`next` の場面へそのまま進みます。

```js
quiz: {
  who: "jolteon",                  // 名前を書かない文は、この仲間のセリフになる
  correct: ["やるじゃん！", "正解！　よく見てるな。", "さすがだぜ！"],   // 正解のセリフ（順に使い、最後の次は最初へ）
  wrong: "おしい！",                // 不正解のセリフ
  questions: [
    {
      unless: "indoor",            // 家の中で進める日は出さない（if・unless が使える）
      before: "見に行くときは、スマホはポケットにな。",   // 問題の前のセリフ（なくてもよい）
      ask: "~…",                    // 問題（"~" は「表示用に隠す」形。ふつうの文でもよい）
      choices: ["~…", "~…", "~…"],  // 選択肢（書いた順に表示する）
      answer: 1,                   // 正解は何番目か（1から数える）
      explain: "~…",                // 解説（正解でも不正解でも出す）
      plus: "~…",                   // 正解したときの補足（なくてもよい。下の注）
    },
    {
      ask: ["雷がピカッと光ってから、…", "雷までは、だいたいどれくらい？"],   // 2行に分けてもよい
      choices: [
        { text: "約100m", reply: "それなら0.3秒くらいで聞こえるはずだ！" },  // 選んだとき「おしい！」の代わりに出す
        { text: "約1km" },
      ],
      answer: 2,
      explain: "答えは約1kmだ！　音は1秒で約340メートル。3秒なら340×3だ。",
      after: "光はほぼ一瞬で届くけど、音はずっとおそいんだ。",   // 解説のあとに出す（正解・不正解とも）
    },
  ],
  score: "{total}問中{n}問正解だ！",   // {total} 出した問題の数、{n} 正解した数
  results: [                        // 正解数のセリフ。count は「出した問題の数: [いくつから, いくつまで]」
    { count: { 10: [0, 2], 5: [0, 1] }, text: "おっと、今回はなかなか難しかったな！　…" },
    { count: { 10: [7, 8] }, text: "おおっ、かなり正解したな！　…" },   // 5問の日は使わない
  ],
},
next: "jolteon_word",
```

- 正解したときは「正解のセリフ＋補足」、不正解のときは「おしい！＋解説」を出します。
- 補足は `plus` です。`plus` がなければ、`explain` の頭の「答えは○○だ！」（「答えは」から最初の「！」まで）を省いた残りを出します。
  `explain` が「答えは」で始まらなければ、正解でも不正解でも、同じ `explain` を出します。
- 出す問題の数は、`if`・`unless` に合う問題の数です（3-1は、外の日10問、家の日5問）。
  `results` は、その数ごとに、0問〜全問のどれにも1つずつ当たるように書きます（`?debug` の点検で確かめられます）。
- 駅に固有の問題・選択肢・解説は、「表示用に隠す」形（`~` で始まる）で書きます（4章）。
  `?debug` の 🛠 →「表示用に隠す」に、「サンダース：」を付けない元の文を入れて作ります。
- 途中で閉じて「つづきから」を押すと、クイズは1問目からやり直しになります。

### 文字を入力させる（input）：なぞなぞ・カードの言葉・名前

```js
input: {
  prompt: "カードに書いてあった言葉は？",
  answers: ["ぬくぬく"],           // 正解（いくつでも書ける）
  next: "flareon_meet",            // 正解したときに進む場面
  wrong: "ブラッキー：……ちがうな。",  // まちがえたときの返事
  hint: [                          // ヒント（押すたびに1つずつ出る。なくてもよい）
    "ブラッキー：冷たいものを冷やすには、熱をどこかへ逃がさないといけない。",
    "イーブイ：冷蔵庫の横の、奥の方を見てみて。",
  ],
  skip: {                          // 救済（なくてもよい）
    after: 3,                      // 3回まちがえたら、ボタンを出す
    text: "見つからない",           // ボタンの文字
    reply: "ブラッキー：……待て。ブースターのほうから、声が聞こえてきた。",
    next: "flareon_meet",          // ボタンを押したときに進む場面
  },
},
```

- ひらがな・カタカナ、全角・半角、空白のちがいは自動で同じものとみなします。
  漢字とひらがなは別の答えになるので、両方を書いてください。
- `name: true` を書くと、入力した文字を主人公の名前として記録します（正解はない）。
- 1-1の名前（`forest_name`）には、`check` を書いています（11/2。設計書 1-1）。
  PCで直接開いたときだけ、入れた名前を `pc-images/name.js` の一覧と照らします（→ 7章）。
  一覧にない名前なら `wrong` を出して、入力にもどります。
  `after` 回（3回）続けて一覧にないと、`wrong` の代わりに `ask`（「もしかして、{guess}？」）で聞きます。
  `{guess}` は、`name.js` の `guess`（呼び名）です。「うん」でその呼び名を名前にして進み、
  「ちがう」で入力にもどります。その後も3回ごとに同じように聞きます。
  一覧で通ったときは、入れたとおりの表記が名前（`{name}`）になります。
  `name.js` がないときは、確認せずに進みます。iPhone（2-4）の名前は確認しません。

  ```js
  input: {
    name: true,
    prompt: "名前を入れよう",
    next: "forest_dream",
    check: {
      wrong: "イーブイ：……本当の名前を忘れちゃったの？　もう一度教えて。",
      after: 3,                               // 3回続けて一覧にないと、ask で聞く
      ask: "イーブイ：もしかして、{guess}？",   // {guess} は name.js の guess
      yes: "うん",                            // 呼び名を名前にして進む
      no: "ちがう",                           // 入力にもどる
    },
  },
  ```
- `hintAfter: 1` を書くと、1回まちがえるまで「ヒント」のボタンを出しません（2-7のエーフィ）。
  `hintAfter: 2` なら、2回まちがえてから出します（2-7の霧の向こうへ行く方法。`espeon_fog_ask`）。
  書かなければ、はじめからヒントを見られます。
- `back: "場面の名前"` を書くと、入力欄に「◀ もどる」ボタンが出て、その場面へもどります。
  2-7では、エーフィの問いかけ（`pc_wait_station`）にもどり、「まだ」を選び直せます。
  2-7の霧の向こうへ行く方法も、イーブイの問いかけと選択（`espeon_fog`）にもどります。
  長い演出のあとに選択と入力欄を置くときは、選択を別の場面に分けると、演出をくり返さずにもどれます。
- `backText` で、もどるボタンの文字を変えられます。2-7のiPhone側は `backText: "◀ まだ"` で、暗い窓へもどります。

```js
input: {
  prompt: "エーフィに伝える言葉",
  // …
  hintAfter: 1,              // ヒントは、1回まちがえてから
  back: "pc_wait_station",   // 「もどる」で、選択肢の場面へもどる
},
```

### 公園で気配を探す（search・GPSヒント機能）

3-1（サンダース）のあと、公園を回って「気配」を見つけると、3-2（リーフィア）が始まります（10/31）。
場面は `leafeon_search` です。iPhoneで開いた公開ページで使います。

- はじめにイーブイ「リーフィアの気配、どこかに残ってるかな。」が出て、「気配を探す」のボタンが出ます。
- 公園で立ち止まり、「気配を探す」を押すと、位置を最大15秒ほど測ります。自動では探しません。
- 押してから15秒たっても位置も返事も届かないときは、「やめる」が出ます。押すと、時間切れと同じ扱いです。
- 公園の順番は問いません。同じ公園は二度数えません。必要な数（初期値3）に達したら、「つづける ▶」で3-2へ進みます。
- 見つけた数や必要な数は、画面に出しません。進み具合は、イーブイの文の変化で伝えます。
- 見つからないときは、続けて3回のあとに「気配を見つけたことにする」が出ます。
  位置情報のエラー（拒否・取得失敗・時間切れ）のときは、1回目から出ます。
  PCや `?debug` で開いて位置が取れなくても、このボタンで最後まで進めます。
- 「つづきから」では、最後に出たヒントの文をもう一度出します（まだ1つも見つけていなければ、はじめの台詞から）。
- 「今日は家の中で進める」の道は、公園を通りません。
- 合言葉「まどのそと」で始め直すと、3-0で公園の記録が空になります（`out_start` の `parkReset: true`）。
- 現在地は、保存も、外部への送信もしません。記録するのは「どの公園で見つけたか」だけです。

| 変えたいもの | 場所 |
|---|---|
| イーブイの文（見つけたとき・気配なし・エラーなど） | 場面 `leafeon_search` の `search` |
| ボタンの文字 | `UI` の `searchButton`・`searchWait`・`searchManual` |
| 半径・精度の上限・必要な公園の数などの設定値 | `SETTINGS` の `gps` |
| どの点がどの公園か | `SETTINGS` の `gps` の `parks`（点は `hidden` の名前） |
| 公園の座標 | `SETTINGS` の `hidden`（`parkA` など。駅名と同じ「表示用に隠す」形） |

座標を変えるときは、🛠 →「表示用に隠す」に「緯度,経度」（例：`12.345678,123.456789`）を入れ、
出てきた `"~…"` を `hidden` に貼りつけます。大きい公園は、入口ごとに点を書きます（公園I）。

**テストページ（`gps-test.html`）**

公開ページの `gps-test.html` で、本編と同じ判定と文を試せます。
`data.js` と `geo.js` を読むので、`data.js` を直すと、テストページも同じに変わります。
記録は `eevee-gps-test` だけを使い、本編の記録には触れません。

### クリアしたなかまへ戻る（REPLAY）

タイトル画面とメニュー（≡）の「なかまの場面へ」から、クリアした仲間の場面を最初から遊べます
（設計書 第11節）。最終章を終える前は、終えたら、話の続きへそのまま進みます。
最終章を終えたあとは、`until` を書いた仲間（PCの3匹）は、終えたら「なかまの場面へ」のメニューへ戻ります（11/3）。
並べる仲間と、始める場面は、`data.js` の `REPLAY` に書きます。

```js
const REPLAY = [
  { who: "glaceon", scene: "glaceon", label: "1-2　氷の洞窟", until: "sylveon" },
  // 友達を仲間に誘うところから遊べるように、1-3 の中だけで使う条件を消す
  { who: "sylveon", scene: "sylveon", label: "1-3　花畑", unset: ["friend1", "friend2", "friend3", "humans"], until: "sylveon_after" },
  // …
];
```

| 項目 | 意味 |
|---|---|
| `who` | 仲間。この端末で、その仲間の言葉（`give: "glaceon"`）を受けとるとクリア |
| `scene` | 遊び直すときに始める場面 |
| `label` | 名前の上に出す、場面の番号と場所 |
| `unset` | 遊び直すときに消す条件（その場面の中だけで使うもの） |
| `until` | 最終章を終えたあと、この場面へ進む所で遊び直しを終え、メニューへ戻る（その場面は始めない） |

| 仲間 | 終える所（`until` の場面へ進む前） |
|---|---|
| グレイシア | 言葉のあとの「挑戦の床」まで遊んで、1-3の花畑（`sylveon`）へ進む所 |
| ニンフィア | 言葉を受けとったあと、花畑を歩いて門へ向かう場面（`sylveon_after`）の前 |
| エーフィ | 言葉のあとの2行（`espeon_2`）のあと、広場を歩いて出る場面（`plaza_exit`）の前 |

- メニューへ戻るときは、いちばん先まで進んだ所にもどしてから保存します。
  なかまノートの言葉・会った仲間・名前は、そのままです。メニューは、タイトル画面の上に開きます。
- iPhoneの5匹（`until` なし）は、今までどおり、終えたら続きへ進みます（PCに並べる形は保留）。

- まだクリアしていない仲間は「？」にして、名前も絵も場所も出しません。
- クリアした仲間が1匹もいないときは、ボタンを出しません。
- 最終章を終えたあとは、タイトル画面の「なかまの場面へ」は「おたのしみ」の中に入ります（メニュー〔≡〕には、今までどおり出ます）。
- 記録はPCとiPhoneで別々です。並ぶのは、その端末でクリアした仲間がいる側だけです。
  場面の `mode` が `"chat"` の仲間は iPhone 側（ふつうは、PCは3匹、iPhoneは5匹）。
  合言葉の場面で引きついだ言葉（`give: [ … ]`）では、クリアになりません。
- 遊び直しても、いちばん先まで進んだ所・なかまノートの言葉・友達の呼び名は減りません。
  「つづきから」は、いちばん先まで進んだ所から再開します（そのときの条件 `set` にもどす）。
- 遊び直しが、いちばん先まで進んだ所に追いつくと、ふつうの記録にもどります。
  追いついたかは、`SCENES` に書いた場面の順番で決めます。場面の順番を入れかえるときは注意してください。
- 2-4（ブラッキー）を遊び直すと、名前をもう一度入れます。入れた名前に変わります。
- サンダースを外の道で遊び直すと、公園の気配探し（`leafeon_search`）を通ります。
  公園で見つけた記録は、遊び直しても消しません（3-0の `parkReset` も、遊び直しの途中は効かない）。
  前に必要な数を見つけていれば、「つづける ▶」ですぐ3-2へ進みます。
  リーフィアを選んだときは、気配探しを通らず、3-2の登場（`leafeon_meet`）から始まります。
- テスト用には、`?debug` の 🛠 →「この場面へ」で、どの場面へもとべます。
  🛠 →「なかまと言葉を全部にする」を押すと、PCとiPhoneの両方の仲間が並びます。

### 4-6のエピローグと終わりの画面（finale・credits）

4-6のエピローグ（`epilogue`）は、イーブイの2行のあと、次の順に進みます（設計書 第8節。11/2）。

1. 会話の枠がゆっくり消えて、雪がふりはじめる（9匹が並ぶ画面のまま。約3秒）。
2. 約1秒の暗転をはさんで、最後のイラスト（`pc-images/ending.png`）に切りかわる。
   画像がないとき・公開ページでは、9匹が並ぶ画面のまま。
3. 右下に ▼ が出たら、クリック（Enter）で終わりの画面へ。1と2のあいだは、クリックしても進まない。
4. 終わりの画面（スタッフの名前）。「タイトルへもどる」で、タイトル画面へ。

- プレゼントを手渡しにする日（`presentOnMap` が `false`）は、1行目が「受け取ってくれた？　よかった……！」になります。
- 終わりの画面の「友情出演」は、PCで `index.html` を直接開いたときだけ出します（条件 `pcDirect`）。
  友達の呼び名は、1-3と同じです（`SETTINGS` の `local`。「表示用に隠す」形）。
- 「つづきから」で開き直すと、終わりの画面から始まります（今までどおり）。

```js
epilogue: {
  show: ["eevee", "glaceon", /* … 9匹 */],
  lines: [
    { if: "presentOnMap", text: "イーブイ：見つかった？　よかった……！" },
    { unless: "presentOnMap", text: "イーブイ：受け取ってくれた？　よかった……！" },
    "イーブイ：またいつでも、夢の部屋で会おうね。{name}、メリークリスマス！",
  ],
  // 文のあと：雪を snow ミリ秒ふらせてから、最後のイラスト（image）へ。暗転の長さは fade（ミリ秒）
  finale: { snow: 3000, image: "ending.png", fade: 1000 },
  end: {
    bg: "christmas",
    snow: true,                 // 終わりの画面にも雪
    title: "イーブイと8つの夢",
    text: "Fin",
    credits: [                  // title と text の下に、1行ずつ出す（「作：パパ」は、そのままの文として出る）
      "作：パパ",
      { if: "pcDirect", text: "友情出演：{friend1}・{friend2}・{friend3}" },   // PCで直接開いたときだけ
    ],
  },
},
```

### クリア後のおたのしみ（BONUS）

最終章を終えると（4-6の終わりの画面を出したあと）、PCのタイトル画面に「🎁 おたのしみ」が出ます（設計書 第11節。11/2）。

| 中のボタン | どうなるか |
|---|---|
| 🔁 なかまの場面へ | 今までの「なかまの場面へ」と同じ（クリアした仲間がいるときだけ）。「◀ もどる」で、おたのしみにもどる |
| ⛄ 雪だるま戦・強いモード | 1-3の雪だるま兄弟との2戦を、数値を上げて遊ぶ。花畑に「パパ」もかくれている（下の「強いモード」） |
| 🖼 回想ギャラリー | 4-3の回想のイラスト8枚と、4-6の最後のイラスト（`ending.png`）を見返す |

- 「最終章を終えた記録」は、`data.js` の4-6（`epilogue`）の `end` の `complete: true` で残します。
  前の版の記録でも、4-6の終わりの画面にいれば、終えたとみなします。「はじめから」と「記録を消す」で消えます。
- 「おたのしみ」が出ているあいだ、タイトル画面の「なかまの場面へ」は、おたのしみの中に入ります。
  プレイ中のメニュー（≡）の「なかまの場面へ」は、今までどおりです。
- 回想ギャラリー：見つかった絵だけを並べます（画像がないものは出しません）。絵をクリックすると大きく見られます。
  大きく見ているときは、←→キー（または「◀ まえ」「つぎ ▶」）で、まえ・つぎの絵。「一覧へ」で並べた画面にもどります。
  絵を探すのは、PCで `index.html` を直接開いたときだけです（7章と同じ `pc-images`）。1枚もないときは、そう出します。
- 並べる絵と、下に出す名前は、`data.js` の `BONUS` の `gallery` に書きます。

```js
const BONUS = {
  gallery: [
    { image: "kaisou/グレイシア.png", label: "グレイシア" },   // pc-images の中の場所と、絵の下に出す名前
    // …
    { image: "ending.png", label: "エンディング" },
  ],
};
```

- 🛠 →「最終章を終えた記録をつける」で、遊び終えなくても「おたのしみ」を試せます。

#### 雪だるま戦・強いモード（パパ）

1-3の花畑で仲間を3人えらび、強くなった雪だるま兄弟と2回戦います（弟戦 → 合体戦）。

1. 花畑（`hard_start`）で、友達3人とパパの4人のうち3人を仲間にする。
   パパは、倒木（本当の家ではソファ）の [12, 5] にかくれていて、姿は見えない（events の `hidden: true`）。
   倒木の右下のチョウチョに話しかける所（[13, 5]）から、左を押すと会える。
2. 3人そろったあとに4人目に話しかけると、「今日は応援してるね！」と言って加わらない。
3. ニンフィアに話しかけて「行く」→ 弟戦（`littleHard`）→ 合体戦（`mergedHard`）。主人公と合わせて4人で戦う。
4. 勝つと、終わりの画面。「もう一度（仲間をえらび直す）」か「タイトルへもどる」。

- 負けたら、その場でやり直さずに、戦いを終えて花畑（仲間を集める所）へもどります（戦いの `retreat`）。
  花畑に入ると仲間の条件を消すので、仲間はえらび直しです（はじめの文は出さず、歩くところから）。
- パパを仲間にせずに負けたときは、パパの声のヒントが出ます（`data.js` の `HARD_HINT`。文言は【仮】）。

| パパなしで負けた回数 | ヒント |
|---|---|
| 1回目 | パパの声：このメンバーじゃ勝てないかも |
| 2回目 | パパの声：こんなとき、パパがいれば |
| 3回目から毎回 | パパの声：パパは、ソファにいるよ |

- パパが仲間にいて負けたときは、ヒントを出さず、回数も数えません。
- 回数は、弟戦と合体戦の合計です。記録（`counts` の `hardLose`）に残すので、日をまたいでも数えます。
  「はじめから」で始め直すと、0 にもどります。
- 強いモードの場面は `bonus: true` です。遊んでも、「つづきから」の場所（いちばん先まで進んだ所）は変わりません。
- パパのコマンドも、ほかの人間組と同じく毎ターン選びます。

| 技 | 効き目 |
|---|---|
| （呼び名）ちゃーん | そのターンだけ、主人公の攻撃が5倍【仮】。かならず効く。そのターンの最初に動く（`first: true`） |
| におう立ち | そのターンだけ、みんなが受けるダメージを0にする。3回に1回くらい【仮】、代わりに「スマホに夢中になって動かない」 |

- 技の名前の呼び名は、PCだけの `pc-images/name.js` の `call` から読みます（7章）。
  呼び名がないとき（`name.js` がない・`call` を書いていない・公開ページ）は、「（名前）ーっ！」になります。
  息子さんの名前と呼び名は、`data.js` に書いていません。効果の文は `{name}` です。
- 戦いで乱数を使うのは、「スマホに夢中」だけです（`MOVES` の `niou` の `fail`。`rate: 1 / 3` が割合）。
- 数値は【仮】です（`BATTLES` の `littleHard`・`mergedHard`、`MOVES` の `papaCall`・`niou`）。
  `?debug` の🛠「戦いの点検」に、仲間の組み合わせ4通りごとの結果が出ます（全部の組み合わせで勝てなくてよい作り）。
  パパがいる組み合わせは、「スマホに夢中にならなければ」の最短と、「スマホに夢中が毎回だと」の結果の両方を出します。

| 書き方（data.js） | 意味 |
|---|---|
| 戦いの `choose: 3` | 主人公のほかに、条件（`if`）のある仲間から3人。条件のない仲間（合体戦のイーブイ・ニンフィア）は、いつも戦う |
| 戦いの `hard: true` | 勝てない仲間の組み合わせがあっても、点検でエラーにしない（どの組み合わせでも勝てないときだけエラー） |
| 戦いの `retreat: { next, hint, lines }` | 負けたら、戦いを終えて `next` の場面へもどる（`lose`・`skip` は使わない）。`hint`（`HARD_HINT`）の `unless` に合わないときだけ、回数（`count`）を数えて、回数に合うセリフを出す。そのあと `lines` |
| 技の `kind: "boost"`・`target`・`power` | そのターンだけ、`target` の仲間の攻撃を `power` 倍にする |
| 技の `first: true` | そのターンの最初に動く |
| 技の `fail: { rate, text }` | `rate` の割合で、技の代わりに `text` を出して何もしない |
| 技の `blocked` | すべて防ぐ技（`guard` の `all: true`）で防いだときの文 |
| 技の名前の `{call}` と `noCall` | `name.js` の `call`（呼び名）／呼び名がないときの技の名前 |

### バックログ（PC）

PCの物語の画面では、今の場面で出た文を、あとから一覧で読みかえせます（設計書 第11節。11/2）。

| 操作 | どうなるか |
|---|---|
| 会話の枠の左下の「ログ」、または ↑キー | 一覧を開く。いちばん新しい文が下に見える。↑↓キー・ホイールでさかのぼれる |
| Esc・「とじる」・一覧の外のクリック | 閉じて、もとの場面にもどる |

- 一覧に出るのは、今の場面で出た文（地の文・セリフ）と、選んだ答え・入れた答え（「▶ …」）、もらった言葉です。
  場面が変わると、空になります。開き直したとき（「つづきから」）も、空から始まります。
- 文を出さずに待っているあいだ（4-3の余韻・絵の暗転・2-7の地図が広がる一拍など）は開けません（ボタンもうすくなります）。
- 4-6の文のあとの演出（雪と最後のイラスト）のあいだは、会話の枠ごと消えるので、開けません。
- 入力欄や選択肢が出ているときも開けます。開いているあいだに Enter を押しても、答えは送られません。
  閉じると、入れかけの文字はそのままで、入力欄にもどります。
- 入力欄に文字を入れているあいだの ↑キーは、ログを開きません（漢字の変換などに使うため）。ボタンでは開けます。
- 歩けるマップでは、↑キーは歩くのに使います。人物と話している間（会話の文・選択肢）は、↑キーでログを開きます。
- 戦いのコマンドを選んでいる間の ↑キーは、コマンドを選ぶのに使います（ボタンでは開けます）。
  戦いの文の途中で開くと、自動で次へ進むのが止まります。閉じたあと、クリック（Enter）で進みます。
- iPhone（メッセージ画面）にはボタンを置いていません。画面を指で下へなぞると、前の文を読めます
  （同じ画面を開いているあいだ。開き直すと、そこからの文だけになります）。
- ボタンや一覧の文字は、`data.js` の `UI` の `logButton`・`logTitle` などです。

### 画面の文字（UI）

ボタンやお知らせの文字は、`data.js` の最後の `UI` にまとめています。
`{n}` や `{who}` などの `{ }` は、ゲームが数や名前に置きかえるので、消さないでください。

## 4. 答えを暗号にする（駅名など）

公開したページは、URLを知っている人なら誰でも中身を読めます。
駅名など、住まいの推測につながる文字は、そのまま書きません。
使い方によって、2つの書き方があります。

| 書き方 | 使う場所 | 元にもどせる？ |
|---|---|---|
| 暗号（`#` で始まる） | 答え（`answers`）と合言葉（`KEYWORDS`） | もどせない |
| 表示用に隠す（`~` で始まる） | 画面に出したい地名（`SETTINGS` の `hidden`）と、3-1のクイズの駅の問題（`quiz`） | もどせる |

**暗号の作り方**

1. ゲームを `?debug` 付きで開き、🛠 →「答えを暗号にする」に答えを入力します。
2. 表示された `"#1a2b3c4d"` のような文字を、`answers` に貼りつけます。
3. 漢字・ひらがな・「駅」つきなど、正解にしたい書き方ごとに作ります。

- 鏡に書く駅名の暗号は、`data.js` の `STATION` に5通り入っています。
  浴室の鏡の答え（2-5）と、PCでエーフィに伝える言葉（2-7）の両方で使います。
- 暗号から元の言葉に戻すことはできません。何の暗号か、手元にメモしてください。

**表示用に隠す（スキップしたときに駅名を見せるため）**

1. 🛠 →「表示用に隠す」に、画面に出したい文字を入力します。
2. 表示された `"~…"` の文字を、`SETTINGS` の `hidden` に貼りつけます。

## 5. 地図を変える（room.js・house.js）

### 夢の部屋（room.js）

1. 実際の部屋を、方眼紙のマス目で描きます（例：横10マス × 縦8マス）。
2. 家具ごとに、左上の位置（`x`, `y`）と大きさ（`w`, `h`）をマスで数えます。
3. `room.js` の数字を書きかえます。

```js
{ name: "ベッド", x: 0, y: 0, w: 3, h: 5, icon: "🛏️", color: "#b9d3f2",
  text: "ふかふかのベッド。", dark: "やわらかいものにさわった。……ベッド、かな？" },
```

- `shine: true` を付けた場所が光ります。ブラッキーのぬいぐるみを置く場所に合わせます。
- 同じ地図を、暗い部屋（2-1）と、明るくなった夢の部屋（2-2）で使います。
- `dark` は、暗い部屋で調べたときの文章です。手ざわりだけを書き、名前は言い切りません。
- `wall: true` を付けた場所は、部屋の外としてぬりつぶします（出窓のまわりなど）。
- 後に書いた物ほど、上に重なります。家具の上に置く物（光る場所など）は、その家具より後に書きます。
- `x` や `w` には `7.5` のような半分の数も使えます。
- 実際の部屋にしかない特徴（ポスターなど）を1つ入れると、自分の部屋だと気づきやすくなります。

- Safariとホーム画面のアイコンでは、記録が別々に保存されます。
  途中からホーム画面のアイコンに切りかえないでください。

## 9. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 「シナリオを読み込めませんでした」と出る | data.js の書きまちがい。直前に編集した場所の `,` `"` `}` `]` を確認 |
| 画面の上に赤い帯が出る | 場面の名前のまちがいなど。帯に書かれた場所を直す |
| 文字化けする | ファイルの文字コードを UTF-8 にして保存し直す |
| 前の記録が残っている | `?debug` を付けて開き、🛠 →「記録（セーブ）を消す」 |
| 記録が残らない | プライベートブラウズでは、タブを閉じると記録が消える |
| iPhoneで途中の場面にもどりたい | `?debug` を付けて開き、🛠 から場面へジャンプ |
| 駅名が分からず、PCで先へ進めない | iPhoneの合言葉待ちの画面で、ヒントを2回押すと駅名が出る |
| 歩けるマップで、矢印キーが効かない | ゲームの画面を一度クリックしてから押す（ほかの欄に文字を入れていると動かない） |
| 友達の呼び名を変えたい | `SETTINGS` の `local` の `default` を書きかえる（4章の「表示用に隠す」） |
| 戦いに勝てない | 負けるとニンフィアがヒントを出す。3回負けると、手伝ってもらうボタンが出る |
| 暗い部屋で、光る○を押しても進まない | ○を押すと、地図の下に「▶ 声を聞く」ボタンが出る。会話の枠のクリック・Enter・○をもう一度押しても進む |
| 光る○を押しても「……机、かな？」と出る | 10/28に直した不具合。新しい版のファイル（直したのは `style.css`）に入れかえて、開き直す |
| 2-2のあと、PCで先へ進めない | ここからは現実の場面。ブラッキーのぬいぐるみのQRコードをiPhoneで読む（なければ、タイトル画面の「あいことばを入れる」に「ゆめのへや」） |
| プレゼントの星に「仮」と出る | 遊ぶPCで、`?debug` →「遊ぶ前の準備：プレゼントの場所」を決める |
| 数値を変えたら、戦いの進み方がおかしい | `?debug` → 🛠 →「戦いの点検」で、何ターンで勝てるかを確かめる |
| 音が鳴らない | メニューの音が「🔊 音：ON」か確かめる。iPhoneはマナーモードを切り、画面を一度タップする。第3部は鳴らさない作り。🛠 →「音の試聴」で鳴るか確かめる |
| 曲（BGM）が鳴らない | `bgm` フォルダが `index.html` と同じ場所にあるか、ファイルの名前が変わっていないか確かめる。曲はPCの場面だけ（2-1・2-2、4-1・4-2、iPhone、第3部は鳴らさない作り） |
| 曲が大きい・小さい | `data.js` の `SETTINGS.bgm` の `volume` を変える（🛠 →「音の試聴」の「▶ 曲：…」で、効果音と聞きくらべられる） |
| iPhoneが暗い窓のまま進まない | 2-7のiPhone側の「待っている画面」。パソコンでエーフィの話を聞いてから、画面をタップする |
| iPhoneで文が先へ進まない | メッセージのところをタップする。文の終わりの ▼ は、タップを待っている印 |
| PCでイラストが出ない | `index.html` を直接開いているか、`pc-images` の場所と画像の名前（7章の表）を確かめる |
| 4-3の回想のイラストが出ない | `?debug` の🛠「PCだけのフォルダ」で、見つからない画像の名前を見る。`pc-images/kaisou` の場所と、名前の打ちまちがい（7章） |
| 4-6の最後のイラストが出ない | `pc-images/ending.png`（`kaisou` の中ではない）か確かめる。🛠「PCだけのフォルダ」で、見つからない画像に出ないか見る（7章） |
| 終わりの画面に「友情出演」が出ない | PCで `index.html` を直接開いたときだけ出す作り（公開ページでは出さない） |
| 1-1で名前を確認しない | `?debug` の🛠「PCだけのフォルダ」で、`name.js` が「読みこめた」と出るか見る。出ないときは、`name.sample.js` と見くらべる（7章） |

**本番前に**：テストで息子さんのiPhoneを使った場合は、記録を消しておいてください。

## 10. 素材について

- このリポジトリと公開ページには、ポケモンの公式画像を入れていません（絵文字と色で表現）。
- 公式のイラストは、PCで直接開いたときだけ、PCに保存した画像を使えます（7章）。
- 公開したページは誰でも見られるため、公式の画像や音楽は載せないでください。
- 効果音は `sound.js` でその場で合成しています（効果音の音声ファイルはありません）。
  ポケモンのゲームやアニメの曲・効果音には似せていません。
- 曲（BGM）は、BGMer のフリー素材です（`bgm` フォルダ。「想い出の魔法」「スリルな黒タイツ」「再会の誓い」）。
  設計書の確認では、規約で商用・改変・再配布とも可、クレジットは任意です。

音楽：BGMer https://bgmer.net/

- `lib/qrcode.js` は Kazuhiko Arase 氏の QR Code Generator（MITライセンス）です。
