# イーブイと8つの夢（最小構成版）

13歳の息子さんへのクリスマスプレゼントと連動した、手作りゲームです。
PCで始まり、ブラッキーのぬいぐるみのQRコードからiPhoneへ移ります。
そのあと、家の中・駅・公園へと冒険が広がり、最後はPCへ帰ってきます。

- 実装の状況・仮置きの一覧・本番までの準備 → [docs/mvp-status.md](docs/mvp-status.md)
- 以前の試作報告（2026年10月21日） → [docs/prototype-report.md](docs/prototype-report.md)

> **設計書と間取り図は、このリポジトリに入れないでください。**
> 公開ページから、答えや駅名、家の間取りが見えてしまいます。

## 1. まず遊んでみる

| 遊ぶ場所 | 開き方 |
|---|---|
| PC | `index.html` をダブルクリック（Chrome・Edge・Safari） |
| iPhone | インターネットに公開したURLを開く（→「8. iPhoneで遊ぶには」） |

PCで直接開いたときだけ、PCに保存した公式のイラストを使えます（→「7. PCで公式のイラストを使う」）。

- 記録は端末ごとに自動で保存されます。次回は「つづきから」で再開できます。
- PCとiPhoneの記録は別々です。端末を移るたびに合言葉でつなぎます。
  合言葉の場面で、それまでに会った仲間と言葉を引きつぎます。
- 「あいことばを入れる」から、合言葉で途中の章を始められます。

| 順 | 合言葉 | 入れる端末 | 始まる場面 |
|---|---|---|---|
| 1 | `ゆめのへや`（ブラッキーのQRコードと同じ） | iPhone | 2-4 ブラッキーとの通信 |
| 2 | 鏡に浮かんだ駅名（暗号で比べる） | PC | 2-7 エーフィの地図 |
| 3 | `まどのそと`（PCの画面に出る） | iPhone | 3-0 出発 |
| 4 | `ただいま`（iPhoneの最後に出る） | PC | 最終章 |

### テスト用メニュー

URLの最後に `?debug` を付けて開くと、右下に 🛠 ボタンが出ます。

- 好きな場面へジャンプ
- なかまと言葉を全部そろえる／記録（セーブ）を消す
- 遊ぶ前の準備：友達の呼び名を、このPCに記録する（→「6. 合言葉・カード・当日の設定」）
- 答えを暗号にする／表示用に隠す（→「4. 答えを暗号にする」）
- 合言葉のQRコードを表示（公開したページで開いたときだけ）
- 氷の床の最短回数（自動で数えた結果）と、data.js の点検結果を表示
- 戦いの点検：何ターンで勝てるか・負けることがあるか（コマンドの選び方を全部ためした結果）

例：`index.html?debug`（PCでは、アドレス欄の最後に `?debug` を書き足す）

## 2. ファイルの役割

| ファイル | 中身 | 編集する？ |
|---|---|---|
| `data.js` | 会話・選択肢・言葉・合言葉・カード・画面の文字（ボタンなど） | **よく編集する** |
| `room.js` | 夢の部屋の地図（家具の位置と、調べたときの文章） | 実際の部屋に合わせて編集 |
| `house.js` | 第1部で歩く地図（和室・リビング・ろうか・洋室・ベランダの形と家具） | 実際の家に合わせて編集 |
| `cards.html` | 印刷用カードのページ | ふつうは不要 |
| `index.html` | ゲームの入口 | ふつうは不要 |
| `engine.js` | ゲームを動かす仕組み（文章は書かない） | 不要 |
| `style.css` | 色や大きさ | 色を変えたいときだけ |
| `icon.png` | iPhoneのホーム画面用アイコン | 差しかえ可 |
| `lib/qrcode.js` | QRコードを作る部品（外部・MITライセンス） | 不要 |
| `pc-images/` | PCだけで使うイラスト（自分で作るフォルダ。GitHub に入れない） | 使うときだけ（→ 7章） |
| `.gitignore` | `pc-images/` を GitHub に入れないための設定 | 不要 |

**文章は `data.js` にあります。**
セリフやボタンの文字を直すときは、`data.js` だけを編集します。
家具を調べたときの短い文章だけは、地図のファイル（`room.js`・`house.js`）の家具の行にあります。
選択肢を足す・場面の順番を変えるといった変更も `data.js` で行えますが、
流れが変わるので、`?debug` の点検で問題が出ないか確かめてください。

**編集するときの注意**

- 保存するときの文字コードは **UTF-8** にしてください（文字化け防止）。
- メモ帳でも編集できますが、[Visual Studio Code](https://code.visualstudio.com/)
  などのエディタを使うと、書きまちがいに気づきやすくなります。
- GitHub のサイト上でも、ファイルを開いて鉛筆マークから直接編集できます。

## 3. 文章を変える（data.js）

会話は `"名前：セリフ"` の形で書きます。名前がない行は地の文になります。

```js
lines: [
  "……ここは、どこだろう。",                 // 地の文
  "イーブイ：あれ？　見かけない顔だね。",     // イーブイのセリフ
],
```

- 行の最後のカンマ `,` を忘れないでください。
- 文章の中で改行したいときは `\n` と書きます。
- `{ }` で囲んだ言葉は、ゲームが置きかえます。

| 書き方 | 置きかわるもの |
|---|---|
| `{name}` | 主人公の名前（1-1でPCに、2-4でiPhoneに入力したもの） |
| `{friend1}`〜`{friend3}` | 友達の呼び名（遊ぶ前にPCで入れておく。`SETTINGS` の `local`） |
| `{station}` | 鏡に書く駅名（`SETTINGS` の `hidden` から） |
| `{park}` | リーフィアのいる公園の名前（同上） |

名前は遊ぶ人が入力します。公開ページに名前を書かないためです。

### 条件つきの行（if・unless）

選んだ道や設定によって、出す行を変えられます。

```js
lines: [
  { unless: "indoor", text: "サンダース：おっそーい！　待ってるあいだに、駅を3周しちゃったよ！" },
  { if: "indoor", text: "サンダース：おっそーい！　待ちきれなくて、窓の外まで走ってきちゃったよ！" },
],
```

- `if` はその条件のときだけ、`unless` はその条件ではないときだけ出します。
- 条件の名前は、選択肢の `set` で記録したものか、`SETTINGS` の設定です。
- 選択肢（`choices`）にも、同じように `if`・`unless` を書けます。

| 条件の名前 | 意味 | 決まり方 |
|---|---|---|
| `indoor` | 外へ出られない日（家の中で進める） | 3-0の選択肢で記録 |
| `useMirror` | 浴室の鏡に駅名を書く日 | `SETTINGS` で切りかえ |
| `presentOnMap` | プレゼントを地図で光らせる | `SETTINGS` で切りかえ |
| `roomMap` | メニューに夢の部屋の地図を出す | 2-2の場面で記録 |
| `charizard` `clefairy` `axew` | リザードン・ピッピ・キバゴが仲間になった | 1-3の花畑で記録 |
| `friends` | 友達（人間組）が仲間になった。2-7のセリフにも使う | 1-3の花畑で記録 |
| `clefairyShy` `clefairyAsk` | ピッピにかくれられた／ニンフィアに頼んだ | 1-3の花畑で記録 |

### 場面（シーン）を追加する

場面には、半角英数字の名前を付けます（例：`jolteon_station`）。

```js
  jolteon_station: {
    bg: "station",                 // 背景
    lines: [
      "サンダース：ビリビリッ！　来たな！",
    ],
    next: "つぎの場面の名前",       // 会話が終わったら進む場面
  },
```

### 場面で使える項目

| 項目 | 意味 | 例 |
|---|---|---|
| `lines` | 会話（上から順に表示） | `["イーブイ：やあ！"]` |
| `next` | 次に進む場面 | `next: "espeon"` |
| `choices` | 選択肢 | 下の例を参照 |
| `input` | 文字を入力させる | 下の例を参照 |
| `end` | 章の終わりの画面 | `end: { title: "…", text: "…", next: "…", nextLabel: "…" }` |
| `mode` | `"chat"` でメッセージ形式（iPhone向け） | `mode: "chat"` |
| `bg` | 背景 | `forest` `ice` `memory` `night` `dream` `home` `station` `park` `christmas` |
| `chapter` | 画面上部に出す章の名前 | `chapter: "第3部　窓の外へ"` |
| `meet` | なかまノートに記録するポケモン | `meet: "jolteon"` |
| `give` | 会話のあとに、そのポケモンの言葉を手に入れる | `give: "jolteon"` |
| `show` | 画面に出すキャラクター（4匹以上なら小さく並べる） | `show: ["eevee", "glaceon"]` |
| `room` | `true` で地図を調べる、`"dark"` で暗い部屋、`"look"` で見せるだけ | `room: "dark"` |
| `ice` | 氷の床のパズル（PCの会話形式の場面だけ） | 下の例を参照 |
| `walk` | 歩けるマップ（`house.js` の地図の名前）。`ice` と一緒なら、その形の氷の床 | `walk: "living"` |
| `events` | 歩けるマップの人物・出入口と、そこで起きること | 下の「歩けるマップ」を参照 |
| `start` | 歩き始める場所と向き `[x, y, 向き]` | `start: [7, 6, "up"]` |
| `goal` | 歩いている間、画面の下に出す目的 | `goal: "仲間を探そう。"` |
| `team` | 集まった仲間を、画面の横に出す | 1-3の `sylveon` を参照 |
| `frost` / `open` | こおった場所を描く `[x, y, 横, 縦]`／開いている扉（出入口の名前） | `open: ["dream"]` |
| `battle` | 戦い（`BATTLES` の名前）。会話のあとに戦いが始まり、勝つと `next` へ | `battle: "snowman1"` |
| `puzzle` | `true` で最後の謎の枠（`PUZZLE`）を表示 | `puzzle: true` |
| `set` / `unset` | 条件の名前を記録する／消す | `set: "roomMap"` |
| `draft` | `true` で「仮の内容」と表示 | `draft: true` |
| `chatTitle` | メッセージ画面の上の名前 | `chatTitle: "イーブイ・サンダース"` |

- `meet` と `give` に `[ ]` で何匹も書くと、お知らせなしで、まとめて記録します。
  合言葉で始まる場面で、それまでの仲間と言葉をそろえるために使います。
- `end` に `next` を書くと、終わりの画面にボタンが出ます。
  開き直して「つづきから」を押すと、終わりの画面から再開します。

### 声だけの人物（voice）

`CHARACTERS` で `voice: true` にした人物は、姿を出さずに名前の札だけ出します。
今は「ブラッキーの声」「エーフィの声」で使っています。

### 氷の床のパズル（ice）

すべり出すと、岩・かべ・ゴールにぶつかるまで止まれないパズルです。
矢印キー（W A S D でも可）、画面のボタン、スマホのスワイプで動かします。

```js
  glaceon_ice2: {
    walk: "washitsu",                        // 和室の形（house.js）の氷の床にする
    lines: ["氷の床に、新しい岩がいくつも現れている。"],
    ice: {
      help: "岩で止まって、向きを変えよう。",   // 遊んでいる間に出す説明
      best: 5,                                // 最短の回数（点検で確かめる）
      map: [                                  // . 氷 / # 岩 / S スタート / G ゴール
        "..G.#....",
        ".#.......",
        "...#.#..S",
        ".#.......",
        "#........",
        "..#.....#",
      ],
      clear: "グレイシア：よく来たわね。",      // クリアしたあとのセリフ
      skip: { after: 3, text: "むずかしい……", reply: "グレイシア：迎えに行くわ。", next: "glaceon_2" },
    },
    next: "glaceon_2",                       // クリアしたあとに進む場面
  },
```

- `S`（イーブイ）と `G`（グレイシア）は、1つずつ書きます。
- `G` にぶつかるとクリアです。クリアすると、最短の回数と比べて表示します。
- `skip` を書くと、「やりなおす」を `after` 回押したあとに、あきらめるボタンが出ます。
- `walk` を書くと、`house.js` のその部屋の形（かべ・出入口）で表示します。
  `map` の大きさ（横と縦のマス数）を、`house.js` の部屋の `w`・`h` に合わせてください。
- 盤面を変えたら、`?debug` の点検を見てください。
  🛠 の「氷の床の最短回数」に、自動で数えた最短の回数が出ます。
  `best` とちがうときや、たどりつけないときは、点検結果にも出ます。
- 今の盤面：練習（`glaceon`）は最短2回、本番（`glaceon_ice2`）は最短5回。
  どちらも解き方は1通りで、行き止まりになる場所はありません。

### 歩けるマップ（walk・events）

第1部の花畑・小道・光の広場は、升目の地図を1マスずつ歩きます。
地図の形と家具は `house.js`、人物と出来事は `data.js` の場面の `events` に書きます。

| 操作 | PC | ボタン |
|---|---|---|
| 歩く | 矢印キー（W A S D でも可） | 右の矢印ボタン |
| 目の前を調べる・話しかける | Enter かスペース | 真ん中の「しらべる」 |

- 人物に向かって歩いても、話しかけられます。
- 目の前に調べられるものがあると、オレンジの点線の印が出ます。
- 出入口（門や扉）は、通りぬけようとすると、その出来事が起きます。

```js
  sylveon: {
    walk: "living",                     // house.js の地図の名前
    start: [7, 6, "up"],                // 歩き始める場所 [x, y, 向き]
    lines: ["ニンフィア：一緒に探して！"],  // 歩き始める前の会話
    goal: "花畑で、仲間を探そう。",       // 歩いている間に出す目的
    events: [
      // 人物：npc（キャラクター）と at（場所）。話しかけると say を出す
      { npc: "charizard", at: [13, 2], unless: "charizard",
        say: ["リザードン：いいぜ。"], set: "charizard" },
      // 同じ人物を何個も書いたときは、条件に合う最初のものが使われる
      { npc: "sylveon", at: [6, 5], if: ["charizard", "friends"],
        say: ["ニンフィア：そろったね！"], next: "sylveon_battle" },
      { npc: "sylveon", at: [6, 5], say: ["ニンフィア：まだ足りないみたい。"] },
      // 出入口：door に house.js の出入口の名前。next で次の場面へ
      { door: "path", next: "path_go" },
    ],
  },
```

| events の項目 | 意味 |
|---|---|
| `npc` / `at` | 人物と場所。何人も並べるときは `npc: ["a", "b"], at: [[1, 2], [3, 4]]` |
| `door` | `house.js` の出入口の名前（`edges` の `id`） |
| `say` | セリフ（`lines` と同じ書き方） |
| `set` / `unset` | セリフのあとに、条件の名前を記録する／消す |
| `next` | セリフのあとに進む場面 |
| `if` / `unless` | 条件に合うときだけ、その人物・出来事を出す |

- 場所は、地図の左上を `[0, 0]` として、右へ x、下へ y と数えます（`house.js` と同じ）。
- 歩いている途中の場所は記録されます。会話から戻ったときや、「つづきから」で、
  その場所から再開します（はじめの会話はくり返しません）。
- 人物を動かしたら、`?debug` の点検で「たどりつけないかもしれません」と出ないか確かめます。
- 歩けるマップの場面には、`next`・`choices`・`input`・`end` を書きません。
  次の場面へは、`events` の `next` で進みます。

### 戦い（battle・BATTLES・MOVES）

1-3の花畑の戦いは、ドラクエ風の選択式バトルです。
2組が1組ずつ順番に戦い、最後に2組そろって決め技を出します。

| 場面 | 戦い（`BATTLES` の名前） | 操作するキャラ | 勝ち方（【仮】） |
|---|---|---|---|
| `sylveon_battle1` | 第1戦 `snowman1`：ポケモン組 × よろい雪だるま | イーブイ | てだすけで、リザードンのほのおを2倍にする |
| `sylveon_battle2` | 第2戦 `snowman2`：人間組 × ころがり雪だるま | 主人公 | 力アップ中に、つかまえる |
| `sylveon_finale` | 決め技 `finale`：2組そろって | 主人公 | 「みんなでいっせいに」を選ぶ |

- 操作するキャラは、毎ターンコマンドを選びます（クリック、または数字のキー）。
- ほかの仲間は、さくせん（`tactics`）のとおりに自動で動きます。
- ハートは組で共通の3つです。0になると負けです。
  ヒントを聞いたあと、その戦いの最初から、ハート3つでやり直します。
- 数値は固定で、乱数は使いません。同じ選び方なら、いつも同じ結果になります。
- 第2戦で3回負けると、ニンフィアに手伝ってもらうボタンが出ます。

```js
const BATTLES = {
  snowman1: {
    title: "第1戦　ポケモン組",          // 画面の左上に出す名前
    hearts: 3,                          // ハート（組で共通）
    leader: "eevee",                    // 操作するキャラ
    commands: ["tackle", "help"],       // コマンド（MOVES の名前）
    party: [                            // 上から順に動く
      { who: "eevee" },                 // 操作するキャラの順番
      { who: "charizard", tactics: "fire" },
      { who: "clefairy", tactics: [{ move: "moonlight", hearts: 2 }, { move: "pound" }] },
      { who: "axew", if: "axew", tactics: "scratch" },   // 仲間にしたときだけ
    ],
    enemy: { who: "snowman1", gauge: "よろい", max: 2, weak: ["fire"], regen: true, blizzard: 2 },
  },
};
```

| 項目 | 意味 |
|---|---|
| `tactics` | さくせん。上から順に調べて、条件に合った最初の技を使う。`hearts: 2` はハートが2以下のとき、`cheer: false` は力アップが切れているとき |
| `gauge` / `max` | 雪だるまのゲージ（よろい・いきおい）と大きさ。0にすると勝ち |
| `weak` | ゲージを減らせる技のタイプ。ほかの技は、はね返される（理由の文 `bounce` が出る） |
| `regen` | `true` なら、減らしきれなかったゲージが、ターンの終わりに元にもどる |
| `damage` / `blizzard` | 雪だるまの攻撃で毎ターン減るハート／何ターンに1回ふぶきが来るか（ハート−1） |
| `hints` / `lose` / `skip` | 戦っている間のヒント／負けたときのヒント／あきらめるボタン |

- 技（`MOVES`）の種類は、`attack`（攻撃）・`help`（てだすけ）・`cheer`（全員の力アップ）・`heal`（ハート回復）です。
- 数値や技を変えたら、`?debug` の 🛠 →「戦いの点検」を見てください。
  何ターンで勝てるか、負けることがあるかを、自動で調べて表示します。
  どう選んでも勝てない戦いになると、点検結果にエラーが出ます。
- 戦いの地の文は、1.1秒たつと自動で進みます（`SETTINGS` の `battleAuto`。0でクリック待ち）。
  キャラクターのセリフは、いつもクリックを待ちます。

### 8つの言葉と最後の謎（word・PUZZLE）

各ポケモンからもらう言葉は、`CHARACTERS` の `word` に書きます。
文字は光らせません。最終章で言葉を枠に入れ、色のついた列を上から読みます。

```js
const PUZZLE = {
  answerColumn: 5,          // 色をつける答えの列（左から何マス目か）
  rows: [
    "・・・・□□□ー□",     // □：言葉が入るマス　・：マスなし　ー：最初から書いてある文字
    // …
  ],
  note: "小さい字（ッ・ャ）も1マス",
};
```

- 言葉を変えるときは、枠の形（マスの数と「ー」の位置）も合わせて直します。
- 答えの列を上から読むと「メリークリスマス」になるようにしています。

### 選択肢（choices）

```js
choices: [
  { text: "一緒に行こう", next: "glaceon" },
  { text: "どうして頼むの？", reply: "イーブイ：……それじゃ、だめかな。" },
  { text: "今日は家の中で進める", set: "indoor", next: "jolteon_meet" },
],
```

- `next` がある選択肢 → `reply`（返事）を表示してから、その場面へ進みます。
- `next` がない選択肢 → `reply` を表示して、選び直しになります（まちがいの選択肢に便利）。
- `set` を書くと、条件の名前を記録します（`unset` で消す）。

### 文字を入力させる（input）：なぞなぞ・カードの言葉・名前

```js
input: {
  prompt: "カードに書いてあった言葉は？",
  answers: ["ぬくぬく"],           // 正解（いくつでも書ける）
  next: "flareon_meet",            // 正解したときに進む場面
  wrong: "ブラッキー：……ちがうな。",  // まちがえたときの返事
  hint: [                          // ヒント（押すたびに1つずつ出る。なくてもよい）
    "ブラッキー：冷たいものを冷やすには、熱をどこかへ逃がさないといけない。",
    "イーブイ：冷蔵庫の横の、奥の方を見てみて。",
  ],
  skip: {                          // 救済（なくてもよい）
    after: 3,                      // 3回まちがえたら、ボタンを出す
    text: "見つからない",           // ボタンの文字
    reply: "ブラッキー：……待て。ブースターのほうから、声が聞こえてきた。",
    next: "flareon_meet",          // ボタンを押したときに進む場面
  },
},
```

- ひらがな・カタカナ、全角・半角、空白のちがいは自動で同じものとみなします。
  漢字とひらがなは別の答えになるので、両方を書いてください。
- `name: true` を書くと、入力した文字を主人公の名前として記録します（正解はない）。

### 画面の文字（UI）

ボタンやお知らせの文字は、`data.js` の最後の `UI` にまとめています。
`{n}` や `{who}` などの `{ }` は、ゲームが数や名前に置きかえるので、消さないでください。

## 4. 答えを暗号にする（駅名など）

公開したページは、URLを知っている人なら誰でも中身を読めます。
駅名など、住まいの推測につながる文字は、そのまま書きません。
使い方によって、2つの書き方があります。

| 書き方 | 使う場所 | 元にもどせる？ |
|---|---|---|
| 暗号（`#` で始まる） | 答え（`answers`）と合言葉（`KEYWORDS`） | もどせない |
| 表示用に隠す（`~` で始まる） | 画面に出したい地名（`SETTINGS` の `hidden`） | もどせる |

**暗号の作り方**

1. ゲームを `?debug` 付きで開き、🛠 →「答えを暗号にする」に答えを入力します。
2. 表示された `"#1a2b3c4d"` のような文字を、`answers` に貼りつけます。
3. 漢字・ひらがな・「駅」つきなど、正解にしたい書き方ごとに作ります。

- 鏡に書く駅名の暗号は、`data.js` の `STATION` に5通り入っています。
  浴室の鏡の答え（2-5）と、PCでエーフィに伝える言葉（2-7）の両方で使います。
- 暗号から元の言葉に戻すことはできません。何の暗号か、手元にメモしてください。

**表示用に隠す（スキップしたときに駅名を見せるため）**

1. 🛠 →「表示用に隠す」に、画面に出したい文字を入力します。
2. 表示された `"~…"` の文字を、`SETTINGS` の `hidden` に貼りつけます。
3. 文章に `{station}` のように書くと、その位置に元の文字で表示されます。

- 元に戻せる形なので、ページの中身をくわしく調べれば読めてしまいます。
  検索や、ちらっと見たときに読まれないための工夫です。

## 5. 地図を変える（room.js・house.js）

### 夢の部屋（room.js）

1. 実際の部屋を、方眼紙のマス目で描きます（例：横10マス × 縦8マス）。
2. 家具ごとに、左上の位置（`x`, `y`）と大きさ（`w`, `h`）をマスで数えます。
3. `room.js` の数字を書きかえます。

```js
{ name: "ベッド", x: 0, y: 0, w: 3, h: 5, icon: "🛏️", color: "#b9d3f2",
  text: "ふかふかのベッド。", dark: "やわらかいものにさわった。……ベッド、かな？" },
```

- `shine: true` を付けた場所が光ります。ブラッキーのぬいぐるみを置く場所に合わせます。
- 同じ地図を、暗い部屋（2-1）と、明るくなった夢の部屋（2-2）で使います。
- `dark` は、暗い部屋で調べたときの文章です。手ざわりだけを書き、名前は言い切りません。
- `wall: true` を付けた場所は、部屋の外としてぬりつぶします（出窓のまわりなど）。
- `x` や `w` には `7.5` のような半分の数も使えます。
- 実際の部屋にしかない特徴（ポスターなど）を1つ入れると、自分の部屋だと気づきやすくなります。

### 第1部で歩く地図（house.js）

2026年10月25日にいただいた間取り図（家具を四角で描いたもの）から作りました。
**間取り図そのものは、このリポジトリに入れないでください。**

| 地図の名前 | 夢での見た目 | 本当の場所 |
|---|---|---|
| `forest` | はじまりの森（1-1） | ベランダ |
| `washitsu` | 氷の洞窟（1-2） | 和室 |
| `living` | ニンフィアの花畑（1-3） | リビング・ダイニング・キッチン |
| `path` | 生け垣の小道 | ろうか・玄関 |
| `plaza` | 光の広場（1-4） | 洋室（息子さんの部屋とは別） |

- 1マスは、およそ45cm です（`room.js` の2マス分）。
- 図面を左へ90度回した向きです。今の夢の部屋（`room.js`）と同じ向きにそろえています。
  2-7で家全体の地図をつなぐとき、向きがそろっている必要があるためです。
- 家具には、2組の見た目を書きます。`nature` は第1部（夢の中）、`home` は本当の家具です。
  2-7で地図が広がるときに、`home` の見た目に切りかえます（作る順番5で作る）。
- かべの出入口と窓は `edges` に書きます。通りぬけられる出入口には `id` を付けます。
- 「開かない扉」は、ろうかの息子さんの部屋のドアの位置（`path` の `dream`）です。
- `toilet` などの場所は、2-7の家全体の地図だけで使います（第1部では歩きません）。

```js
{ x: 9, y: 5, w: 4, h: 2,
  nature: { name: "倒木", icon: "🪵", color: "#a8825a", text: "大きな木が倒れている。" },
  home:   { name: "ソファ", icon: "🛋️", color: "#b9a3d6" } },
```

家具を動かしたら、`?debug` の点検で、はみ出しや、たどりつけない人物がないか確かめます。

## 6. 合言葉・カード・当日の設定

- 合言葉は `data.js` の `KEYWORDS` に、「場面の名前: [合言葉, …]」の形で書きます。
- カードの文章は `data.js` の `CARDS` に書きます。
- `cards.html` を開いて「印刷する」を押すと、A4用紙にカードを印刷できます。
- QRコードを印刷するには、公開URLを `SETTINGS.siteUrl` に書いてください。
  QRコードを読むと、`index.html?key=合言葉` が開き、その場面から始まります。
- `blank` を書いたカードには、手で書きこむ空らんが印刷されます（駅名用）。
- `label` を書くと、合言葉の見出しを変えられます（ブースターの「カードの言葉」）。

**遊ぶ前の準備：友達の呼び名（このPCだけに記録）**

1-3の花畑に、息子さんの友達3人が出てきます。
友達の呼び名は、公開ページに書かないため、遊ぶPCで入力しておきます。

1. 遊ぶPC・遊ぶブラウザで、ゲームを `?debug` 付きで開きます。
2. 🛠 →「遊ぶ前の準備」に、3人の呼び名を入れます（入れるとすぐ記録されます）。
3. 入れていないときは、「ともだちA」などの仮の呼び名で表示されます。

- 記録はこのPCのブラウザだけに残ります。「記録（セーブ）を消す」でも消えません。
- PCで開くURL（ファイルを直接開く／公開URL）を変えると、記録は別になります。
  息子さんが遊ぶのと同じ開き方で入れてください。
- 3人の並び順は、戦いの技（`SETTINGS` の `local` の `label`）に合わせてください。

**当日の準備に合わせて切りかえる設定（`SETTINGS`）**

| 設定 | true のとき | false のとき |
|---|---|---|
| `useMirror` | 浴室の鏡に駅名を書く（「鏡を見ていて」） | 鏡のそばのカードで代用（「鏡のまわりを見てみて」） |
| `presentOnMap` | プレゼントを隠し、家の地図で光らせる | 家の人が手渡す（「メリークリスマス」が合図） |

- `presentOnMap` は、家全体の地図ができるまで `false` のままにしてください。

**安全のために**

- おふろ場のカードは、ラミネートや袋で防水してください。
- 台所では、火やコンロを使わせない文章にしています。カードは冷蔵庫の横に置きます。
- 外の場面は、家の人が同行する前提の文章です。歩いている間は画面を見ない作りです。

## 7. PCで公式のイラストを使う（PCだけ・インターネットに出さない）

PCで `index.html` を直接開いたときだけ、PCに保存した画像をキャラクターの絵に使えます。
iPhone（公開したページ）では、今までどおり絵文字と色で表示します。

| 開き方 | イラスト |
|---|---|
| PCで `index.html` を直接開く（ダブルクリック） | 使う（`pc-images` フォルダに画像があれば） |
| 公開したURLを開く（iPhone・PCとも） | 使わない（画像を読みにいかない） |
| メッセージ画面（iPhoneの場面） | 使わない |

物語の決まり（PCは夢の世界で、ポケモンが本当の姿で現れる）とも合っています。

**手順**

1. GitHub でこのリポジトリを開き、ブランチ `claude/bold-planck-5orak6` を選ぶ。
2. 「Code」→「Download ZIP」で、PCに保存して展開する。
3. `index.html` と同じ場所に、`pc-images` という名前のフォルダを作る。
4. 画像を `pc-images` に保存し、下の表の名前にする（PNG・WebP・JPG のどれでもよい）。
5. `index.html` をダブルクリックして遊ぶ。

| キャラクター | 画像の名前 | キャラクター | 画像の名前 |
|---|---|---|---|
| イーブイ | `eevee.png` | シャワーズ | `vaporeon.png` |
| グレイシア | `glaceon.png` | ブースター | `flareon.png` |
| ニンフィア | `sylveon.png` | サンダース | `jolteon.png` |
| エーフィ | `espeon.png` | リーフィア | `leafeon.png` |
| ブラッキー | `umbreon.png` | リザードン | `charizard.png` |
| キバゴ | `axew.png` | ピッピ | `clefairy.png` |

- 最後の `.png` は、`.webp` や `.jpg` でもかまいません。
- 背景が透明な画像（PNG・WebP）だと、丸の中にきれいに収まります。
- 画像のないキャラクターは、絵文字のままです。人物・雪だるま・花畑の住人は絵文字です。
- 画像の名前は、`data.js` の `CHARACTERS` の `art` で変えられます。
  `art` を書き足せば、ほかのキャラクターにも画像を使えます。
- 使わないときは、`data.js` の `SETTINGS` の `pcArt` を `""` にします。

**注意**

- **`pc-images` フォルダは、GitHub に入れないでください。**
  `.gitignore` で除外していますが、GitHub のサイトの「Upload files」で入れると公開されます。
- 公式のイラストには著作権があります。家の中で、家族で遊ぶ範囲で使ってください。
- PCの記録と友達の呼び名は、開き方ごとに別です（直接開く／公開URL）。
  PCの場面は最初から最後まで、直接開いて遊んでください。
  「遊ぶ前の準備」（友達の呼び名）も、直接開いた画面で入れてください。
- 新しい版をダウンロードしたときは、`pc-images` フォルダを新しいフォルダへ移します。
- 画像が1枚もないと、開発者ツールの Console に「ERR_FILE_NOT_FOUND」が8件ほど出ます。
  画像を探した記録なので、問題ありません。

## 8. iPhoneで遊ぶには

iPhoneで遊ぶには、ゲームをインターネット上に公開する必要があります。
駅や公園では、自宅のWi-Fiが届かないためです。

主な公開方法（いずれも、URLを知っている人は誰でも開けます）：

| 方法 | 費用 | 特徴 |
|---|---|---|
| GitHub Pages（リポジトリは非公開のまま） | GitHub Pro（有料）が必要 | 設定がいちばん簡単。編集するとすぐ反映される |
| Cloudflare Pages や Netlify | 無料プランあり | 別サービスへの登録と、GitHubとの連携が必要 |
| リポジトリを公開して GitHub Pages | 無料 | シナリオや部屋の地図も誰でも見られる |

※ 料金や画面の手順は変わることがあるため、各サービスの最新情報を確認してください。

### リポジトリを公開して GitHub Pages を使う手順

公開したリポジトリは、ログインしなくても誰でも中身と変更の履歴を読めます。
GitHub の検索や、Google などの検索結果に出ることもあります。

1. GitHub でこのリポジトリを開き、「Settings」を押す。
2. 「General」のいちばん下の「Danger Zone」で「Change visibility」→「Public」にする。
3. 左のメニューの「Pages」を開く。
4. 「Build and deployment」の「Source」を「Deploy from a branch」にする。
5. 「Branch」で `claude/bold-planck-5orak6`、フォルダは `/ (root)` を選び、「Save」を押す。
6. 数分待つと、`https://kurataka123-ctrl.github.io/game/` で開けるようになる。

- このURLは、`data.js` の `SETTINGS.siteUrl` に設定済みです。
- ほかの方法で公開するときは、`siteUrl` をそのURLに書きかえてください。

### 遊ぶときの注意

- QRコードを読むと、iPhoneのSafariでゲームが開きます。
- Safariとホーム画面のアイコンでは、記録が別々に保存されます。
  途中からホーム画面のアイコンに切りかえないでください。

## 9. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 「シナリオを読み込めませんでした」と出る | data.js の書きまちがい。直前に編集した場所の `,` `"` `}` `]` を確認 |
| 画面の上に赤い帯が出る | 場面の名前のまちがいなど。帯に書かれた場所を直す |
| 文字化けする | ファイルの文字コードを UTF-8 にして保存し直す |
| 前の記録が残っている | `?debug` を付けて開き、🛠 →「記録（セーブ）を消す」 |
| 記録が残らない | プライベートブラウズでは、タブを閉じると記録が消える |
| iPhoneで途中の場面にもどりたい | `?debug` を付けて開き、🛠 から場面へジャンプ |
| 駅名が分からず、PCで先へ進めない | iPhoneの合言葉待ちの画面で、ヒントを2回押すと駅名が出る |
| 歩けるマップで、矢印キーが効かない | ゲームの画面を一度クリックしてから押す（ほかの欄に文字を入れていると動かない） |
| 友達の呼び名が「ともだちA」のまま | 遊ぶPCで、`?debug` →「遊ぶ前の準備」に入れる（開くURLが同じか確認） |
| 戦いに勝てない | ターンの始めや負けたときに、ニンフィアがヒントを出す。第2戦は3回負けると、手伝ってもらうボタンが出る |
| 数値を変えたら、戦いの進み方がおかしい | `?debug` → 🛠 →「戦いの点検」で、何ターンで勝てるかを確かめる |
| PCでイラストが出ない | `index.html` を直接開いているか、`pc-images` の場所と画像の名前（7章の表）を確かめる |

**本番前に**：テストで息子さんのiPhoneを使った場合は、記録を消しておいてください。
